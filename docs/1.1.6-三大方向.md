## 0. 三个缺口

| 维度 | 现在有什么 | 缺什么 | 缺的后果 |
|---|---|---|---|
| 时间 | `chronicle` 从文明起点推到顶点（赫利孔 21,116 年） | 起点**之前**的地质史 | 读者问「这块大陆从哪来、那些山为什么在那」 |
| 表达 | `naming` 的音系由 `meta.id` 的字母拼出来 | 从**生理与大气**反推的音系 | **名字是最难伪造的证据**，一个与物理无关的名字会瞬间破功 |
| 关系 | 一个文明、一条史；战争一条、瘟疫一条 | 多文明与接触 | 「争地」没有对手，「大疫」没有路线，等于没写 |

三个方向各自独立，但合起来才有意思：
**深渊给你一片大陆的来历，舌给这片大陆上的东西起名，接触让两个名字相遇。**

三者的共同点，也是它们能进盘古的唯一理由：**都不编故事，只回答「凭什么」。**

## 1. 深渊 · 地质史（`geohistory`）

### 1.1 缺口

`world.json` 是一张**快照**。板块有 `plate` / `boundary` / `motion`（`_tectonics` 已经算出来了），
但没有任何东西把它积起来——所以 `relief_km = 8.8` 只是一个数，不是「两亿年前这里撞过一次」。

### 1.2 状态量与分辨率（先把数字摆出来）

从 `mapgen.py` 读到的真实参数：

| 量 | 值 | 出处 |
|---|---|---|
| 网格 | `DEFAULT_RES = (360, 180)` = **64,800 格** | `mapgen.py:42` |
| 格距 | 赤道处 `2πR/360 ≈ 111 km`，经向 `πR/180 ≈ 111 km` | `_sample_grid` 的 `dx/dy` |
| 板块数 | `clamp(6 + 2.2·R⊕, 6, 16)` | `_cfg` |
| 板块种子 | 球面低差异序列 + ±0.25 rad 抖动，**十几个点** | `_plate_seeds` |
| 板块归属 | 最近种子（点积最大）= 球面 Voronoi | `_tectonics:342-353` |
| 运动向量 | 切平面内单位方向 × `sp ∈ [0.35, 1.0]`，**没有物理单位** | `_tectonics:357-364` |
| 高程上限 | `max_relief = 8.8 / max(0.35, g^0.8)` km | `_cfg:227` |

两件事立刻可算：

- **速度要标定**：`sp` 是纯数，必须乘一个参考速度才有 cm/yr。取 `V_REF = 5 cm/yr`（可被 `tectonics.plate_speed_cm_yr` 覆盖），于是板块速率 1.75–5.0 cm/yr——地球上真实板块就是这个量级。
- **角速度而不是线速度**：`ω = v/R = 0.05 m/yr ÷ 6.371e6 m = 7.85e-9 rad/yr`。五亿年 = **3.9 rad ≈ 225°** 的大圆。这个数说明两件事：回推**必须**是球面旋转（线性平移会把板块推出球面），而且 5 亿年足够让任意两块板块相遇一次——超大陆在长时间尺度上不是巧合，是几何必然。

### 1.3 回推的数学

原稿写的是 `pos(t) = slerp(seed_p, seed_p + v_p·t, 1)`：端点归一化之后它其实就是旋转，
但写成 `slerp` 会让人以为在插值，也埋掉了「面积守恒」这个唯一能验收的性质。准确写法是**轴角旋转**：

```
ω̂_p = (seed_p × m_p) / |seed_p × m_p|        # 旋转轴 = 种子 × 运动方向
ω_p = |m_p| · V_REF / R                        # rad/yr
pos_p(t) = R(ω̂_p, −ω_p·t) · seed_p             # 反推 = 负角
```

`R` 是罗德里格斯公式，**等距变换**：球面多边形的面积、边长、夹角全部精确守恒。
这就是 §1.4 能成立的全部理由。

三块以上板块的**相对**运动不闭合（球面上三个刚体运动一般不可同时满足），
所以回推必然产生「重叠」与「裂缝」——这不是 bug，这就是造山与裂谷的来源（§1.5）。

### 1.4 板块形状：Voronoi 面积会漂（原稿第一处会翻车的地方）

原稿的验收 G02 写「回推 5 亿年后，板块面积总和守恒（±1%）」。**用 `_tectonics` 现在的做法，这条过不了。**

原因：板块归属是「最近种子」的 Voronoi 划分。种子一移动，Voronoi 边界就跟着重划——
细胞面积不再守恒，只有**总面积**守恒。所以：

- 「所有板块面积之和」永远守恒（就是球面积），这条验收等于废话；
- 「单块板块面积守恒」必然漂移，而物理上板块是刚性的，面积不该变。

两条出路，**必须选一条并写进契约**：

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A. 旋转多边形 | 初始 Voronoi 细胞裁成球面多边形（大圆边），之后每帧只旋转顶点 | 要写球面 Sutherland–Hodgman，约 120 行 | **推荐**：面积精确守恒，G02 才有意义 |
| B. 每帧重 Voronoi | 沿用现成代码 | 面积漂移 → G02 只能降级成「漂移 < 5%」 | 不诚实，等于把验收改成凑数 |

方案 A 的额外好处：多边形顶点数 ~20×16 = 320 个，比 64,800 格便宜两个数量级；
渲染古地理时把多边形栅格化（点在多边形内测试用 `dot(v, face_normal) > 0` 逐个面判），
仍然是 O(格 × 面) 但只在出图时算 5 帧。

**这是三个方向里唯一需要新算法的部分，也是它被排在最后的理由。**

### 1.5 高程：不预测山高，只给山一个年龄

原稿说 `G03` 造山「抬升 `relief_km`」。但 `relief_km` 是 `mapgen` 用 `8.8/g^0.8` 定的**上限**，
地质层再去「抬」它，两处就会打架（谁说了算？）。

改成：**山高是已知量，年龄是未知量。**

```
u   = α · v_conv                     # 抬升速率，α = 0.2 mm/yr per (cm/yr)  [经验]
h∞  = max_relief (mapgen 的上限)      # 抬升的渐近线：地壳强度 + 重力
τ_u = h∞ / u                          # 抬升时间常数
t   = −τ_u · ln(1 − h / h∞)           # 反解：长出当前高度用了多久
```

赫利孔北脊：`v_conv = 4.1 cm/yr` → `u = 0.82 mm/yr`，`h∞ = 8.8 km` → `τ_u = 10.7 Myr`，
当前 `h = 0.9·h∞` → **t ≈ 25 Myr**。这数字可以拿去和地球对：喜马拉雅 5 mm/yr 抬升、
~50 Myr 历史、8.8 km 高——同一个数量级，且公式里没有一个自由参数是编的（`α` 是唯一标定量，写进契约）。

`α = 0.2` 的标定依据：让「4 cm/yr 的接缝在 2500 万年内到 9 成高度」与地球最年轻的高山对得上。
换一个重力更高的世界，`h∞` 自己会降（`g^0.8`），山更矮、寿命更短——这是**自洽的连锁**，不是巧合。

### 1.6 海平面：两种面积不能混（原稿第二处会翻车的地方）

原稿的 frames 里 `land_fraction` 从 0.19 涨到 0.24，同时 G02 要求面积守恒——**自相矛盾**。
要拆成两个量：

| 量 | 含义 | 守恒吗 |
|---|---|---|
| **陆壳面积** `crust_area` | 所有板块多边形覆盖的面积 | 守恒（旋转是等距变换） |
| **出露面积** `land_fraction` | 海平面以上的面积 | **不守恒**，随高程分布与水量变 |

出露面积怎么变？三个真实机制，全部有出处：

1. **碰撞加厚**：两块大陆相撞 → `h∞` 局部抬高 → 高程分布整体上移 → 同样水量下出露更多；
2. **大火成岩省**：`G04` 在几十万年里堆出几公里厚的玄武岩 → 瞬时出露；
3. **水量不变**：水账来自 `ledger`（`4πR²·mean_depth·ocean_fraction`），地质层**不许改水量**，
   只许用 `mapgen._solve_sea(height, area, volume)` 重解海平面——这个函数已经存在，签名刚好。

所以 G02 的正确写法是：**`crust_area` 守恒 ±1%；`land_fraction` 与海平面的变化必须能用
「高程分布 + 固定水量」解释**。后者是软断言（写入报告供人看），前者是硬断言。

### 1.7 碳循环：`chem.step_co2` 的显式欧拉在这儿会炸

`chem.py` 的现状：

```python
WEATHER_TIMESCALE_YR = 2.0e5
w    = (co2 / CO2_0) * exp((T - T0) / 13.7)
flux = (1.0 - w) / WEATHER_TIMESCALE_YR
co2  = co2 + flux * dt * CO2_0
```

`dt = 1 Myr` 时 `flux·dt ≈ 5`，一步就把 CO₂ 打到负值——**显式欧拉在 1 Myr 步长上不稳定**。
地质层要跑 500 Myr，稳定步长必须 `dt ≲ τ/10 = 2e4 yr`，那就是 25,000 步，
每步还要调一次 `radiation.solve`——能跑，但没必要。

改用**指数积分**（局部线性化的解析解），`dt` 可以取到 `τ = 2e5 yr`，步数降到 2,500：

```
co2_{n+1} = co2_eq(T_n) + (co2_n − co2_eq(T_n)) · exp(−dt/τ)
co2_eq(T) = CO2_0 · exp(−(T − T0)/13.7)      # 令 w = 1 反解
```

`T_n` 自己又是 `co2_n` 的函数（`radiation.solve`），所以每步做 2–3 次不动点：
`T ← solve(co2)`，`co2_eq ← co2_eq(T)`，误差 < 0.1 K 即停。这条是**数值格式**，不是新物理：
物理仍是那个碳-硅酸盐恒温器，`kernel` 里已经对过解析解。

顺带得到一件真东西：**冰期的判据不再是阈值，而是「CO₂ 平衡点低于 560 ppm 且冰线越过 45°」**。
冰线用现成的纬向温度曲线整体平移 `ΔT = solve(co2) − solve(co2_now)`，
在曲线上找 263 K 的纬度。**已知近似：没有冰-反照率正反馈**（`atmos.py` 里那条在全局尺度上算，
地质层只做平移），记进限制。

### 1.8 事件阈值：每条都要能被「不触发」验收

原稿给了 G01–G06 六个事件，但只有触发条件没有数值。补齐（`[经验]` 为标定，`[几何]` 为可直接算）：

| 事件 | 判据（可算） | 数值 | 性质 |
|---|---|---|---|
| `G01` 超大陆聚合 | 两两质心大圆距离的均值 / (πR) | < 0.42 触发 | [几何] |
| `G02` 超大陆裂解 | 同上比例从 >0.42 跌到 <0.30，且至少一条张裂边界贯通 | — | [几何] |
| `G03` 造山 | `v_conv > 1.5 cm/yr` 且落点 `boundary == 1` | 抬升率见 §1.5 | [经验] |
| `G04` 大火成岩省 | 板块多边形扫过 `hotspot` 格，跨度 < 5 Myr | CO₂ 注入 300–1200 ppm | [经验] |
| `G05` 冰期 / 温室期 | §1.7 的 CO₂ 平衡点与冰线纬度 | 冰线 < 45° = 冰期 | [几何] |
| `G06` 大灭绝 | 冰期 + 出露面积骤降 > 15%（万年内） | — | [经验] |

「不触发」也要有理由：报告里每个事件给一行 `observed: true/false` + 为什么。
读者问「为什么这个世界没有超大陆」，答案必须是「因为五亿年只够扫 225°，而它有三块大陆反向漂」——
而不是「这条规则没命中」。

### 1.12 与 `mapgen` 的接口（要改的三处）

1. **暴露种子与运动**：`_tectonics` 返回的字典里有 `seeds` / `motion` / `cont`，
   但 `MapResult` 只带了 `plate` / `boundary` / `hotspot`（`mapgen.py:146-148`）。
   给 `MapResult` 加三个带默认值的字段（`plate_seeds` / `plate_motion` / `plate_cont`，
   `default_factory=list`，旧调用不受影响）+ `build()` 里三个 kwargs ≈ **六行**。
   这是 `geohistory` 的第一处依赖，也是唯一需要改 `mapgen` 的地方。
2. **复用 `_solve_sea`**：`_solve_sea(height, area, volume)` 已经是纯函数，直接 import，不要复制。
3. **复用地形渲染**：`geohistory --png` 走 `_render_layer` 的高程路径，只是把 `res.elev` 换成「按多边形旋转后重算的高程」。

**不要动 `_tectonics` 的算法**：Voronoi 归属是 `map` 这一层的地形来源，改了会连带 `benchmark` 与所有存档。
地质层只能在外面**再长一层**，这也是它必须自己裁多边形的理由。

### 1.13 会翻车的地方

| 症状 | 原因 | 对策 |
|---|---|---|
| 回推几步后板块互相穿插、图上出现鬼影 | 用 Voronoi 重划分而不是旋转多边形 | §1.4 方案 A |
| 面积漂 2–8%，G02 怎么调都不过 | 同上 | 同上；漂移是 Voronoi 的固有性质 |
| 南北极附近图形畸变 | 用欧拉角而非四元数/轴角 | 全程轴角，`R(ω̂,θ)` 在极区无奇异 |
| CO₂ 一步跳到负值 | `dt=1 Myr` 配显式欧拉 | §1.7 指数积分 |
| 冰期一触发就再也不退出 | 冰-反照率没建模，却按有反馈调了阈值 | §1.7 的平移近似 + G05 的单调性断言 |
| 超大陆判定在 `plates < 3` 时随机乱跳 | 均值距离在两点时退化成距离本身 | `plates < 3` 直接 skip 并注明 |
| 末帧和地图对不上 | 用了另一套海平面解 | 水量只从 `ledger` 读，不自造 |

### 1.14 不做什么

- 不做地幔对流（N 体 + 流体，不是这个尺度能碰的）
- 不做古地磁倒转、不做板块重建的精确年代（只给 ±5% 的近似）
- 不做俯冲板片几何（只记「汇合速率」这一个标量）
- 不做超过 5 帧的动画（PNG 帧 ×5 已 1 MB）

## 2. 舌 · 语言（`lexicon`）

### 2.1 缺口

`civilization` 里所有专名都是作者拍的。`"灰阶诸城"` 与这颗星的重力、大气、日长毫无关系。
这不是审美问题，是**可信度问题**：读者可以原谅一个没解释的重力，但会立刻察觉一个不该存在的词。

### 2.2 与 `naming` 的关系：不是替代，是接管（原稿漏掉的冲突）

`naming` 已经在做一半的事，而且它的音系来源是**错的**：

```
naming.py:112   cons = [c for c in letters if c not in VOWEL_LETTERS]   # 从 meta.id 抽字母
naming.py:116   if len(cons) < 8 or len(vow) < 4:  ← 默认池补位
naming.py:156   s = choice(consonants) + choice(vowels) + [coda]
```

`helikon` 于是得到 `h l k n × e i o`。这个音系与重力、大气、呼吸全部无关——
它是**作者 slug 的回声**。1.1.6 的 `naming` 救的是「可复算与可拆解」，没救「凭什么」。

所以 `lexicon` 的定位是**上游**，不是平行品：

| 层 | 负责 | 输出 |
|---|---|---|
| `lexicon` | 音系从物理反推、词表、词汇缺口 | `civilization.lexicon.phonology` |
| `naming` | 给定音系，生成人名与地名（含音节拆分、双 hash 对账） | `civilization.names` |

**接管规则**（一行改动，`naming.py` 的 6 处逻辑不动）：

```python
# naming.phonology(world) 里加在最前面（naming.py:101）
lex = ws._get(world, "civilization", "lexicon", "phonology", default=None)
if isinstance(lex, dict) and lex.get("consonants"):
    return {**lex, "origin": "lexicon"}     # 用物理音系，不再抽 slug
```

于是：没有 `lexicon` 的旧世界行为完全不变（V24–V27 仍绿）；
有 `lexicon` 的世界，`naming --check` 的两份 hash 重新对账，`origin = lexicon`。
**这条要写进验收**（L05），否则两层会各说各话。

### 2.3 从五个物理量到四个声学指标

原稿给了一张「物理条件 → 音系影响」的表，但没有把物理量算进去。补上公式：

```
L  = 0.17 m · (1/g)^0.33                    # 声道长 ∝ 体型，g 为世界表面重力
f0 = 120 Hz · (0.17/L)                       # 基频 ∝ 1/声道长
s  = 0.17/L                                  # 共振峰整体缩放：F1,F2 × s
```

赫利孔 `g = 1.76` → `L = 0.141 m`（短 2.9 cm），`s = 1.20`，`f0 = 145 Hz`（高约 3 个半音）：
**元音四边形整体放大 20%**，前后位的对立更容易维持。
一条可检验的推论：他们的语言里 `i/u` 的对立比 `e/o` 更稳。

```
asp = 0.7 · (ρ/ρ_E)          # 送气对立能否维持 [经验]：湍流噪声能量 ∝ ρ·U³
voi = 1.0 if P_atm ≥ 80 kPa else 0.6   # 浊音能否跨声门维持 [经验]
abs = (ρ_E/ρ) · (c_E/c)^3    # 经典吸收系数之比：>1 = 声音传得更远
```

`asp ≥ 0.7` 才允许送气清塞音成对立；`abs > 1.5` 的世界，声音传得远 →
**呼唤型语言**（长元音、远距离可辨的双音节呼名）更容易稳定；
`abs < 0.7` 的世界，声音衰减快 → 音系趋向「近距离、高冗余」（更多辅音对立）。

这三个数写进报告，且每条都要能反查（`src` 指到 `atmosphere` / `physics` / 派生表）。

### 2.4 音段池与加权抽取（可复算）

池子是**固定**的（IPA 子集，36 音段：18 辅音 × 8 元音 × 10 其他），抽取按权重：

```
w(c) = 1.0 · [送气可用 ? 1 : 0]  · [浊音可用 ? 1 : 0.6]  · freq_prior(c)
```

`freq_prior` 是跨语言的类型学先验（`p t k m n s l` 高、`q ʕ ɬ` 低）——
**这是唯一「引外部数据」的地方**，写进契约并接受审查：它决定了所有世界都「像人类的语言」，
这正是我们想要的（不像地球的随机字母更糟）。抽 8–14 辅音、4–7 元音、2–4 韵尾，
不足则回落到 §2.2 的默认池，`borrowed` 记账。

### 2.5 音位配列与音节结构

```
响度阶（sonority）：塞音 < 擦音 < 鼻音 < 流音 < 滑音 < 元音
onset 允许：单个辅音，或「塞音/擦音 + 流音/滑音」（响度单调上升）
coda  允许：鼻音 / 流音 / 不除阻塞音，且 ≠ 后续 onset 的同部位音
```

音节模板 `CV(C)`，`V` 可带长短对立（`abs > 1.5` 的世界强制有长元音）。
这在 `naming` 里是 45% 概率加韵尾，在 `lexicon` 里改成**受配列约束的概率**：
`P(coda) = 0.35 + 0.2·(abs ≥ 1.5)`，且 coda 必须过同部位检验。

一条容易被忽略的规矩：**词形在词表内不许重名**。`naming` 有重名检测（`dup`），
`lexicon` 的词表更需要——120 个概念的词形冲突率在 CV 池上会到 8%，
必须用「生成即查重、冲突则升一音节」的循环，且这个循环是确定性的（不重掷 seed）。

### 2.6 语义表：120 + 40，后半张有条件门

| 组 | 数量 | 例 |
|---|---|---|
| 基础（Swadesh 式） | 120 | 水、火、石、走、死、二、我 |
| 世界特有 | 40 | 双影、长明之刻、晨昏线、两段睡眠、锈林、潮线 |

后半张**只有这个世界有**：每个概念挂一个 `gate`，指向 `entail` 的规则编号：

```json
{"concept": "双影", "gate": "E01", "why": "≥2 恒星"}
```

`gate` 不成立 → 这个概念不进词表（并且反过来：E01 成立而词表里没有「影」，
说明词表生成漏了，`--check` 报错）。这让语言层与天象层**互相约束**，
而不是各写各的。

### 2.7 词汇缺口：必须挂在 `E` 编号上

原稿的缺口表很好，但要补「凭什么」的机器可验形式：

| 世界特征 | 不该有的词 | 替代 | 依据 |
|---|---|---|---|
| 没有真正黑夜（`E31`） | 黎明、黄昏、守夜 | 「双影最短之刻」「长明之刻」 | 天光不会降到夜 |
| 潮汐锁定 | 南北、四季 | 「向光」「背光」「晨昏线」 | 无自转 → 无季节 | 
| 长日（`H22`） | 通宵、熬夜 | 「前睡」「后睡」 | 作息被切成两段 |
| 无卫星 | 月、朔望 | 用恒星合代替 | 无潮汐表可背 |
| 峰值 < 480 nm | 「红」作为基本色 | 只有两级明暗 | 环境光里没有红 |

`--check` 做的事：把每条缺口的 `gate` 重算一遍。世界改了设定（比如把三星改成单星），
`E31` 失效，「黎明」这个词就该还回来——**语言层因此会随物理层一起翻新**，
这是它值得做的根本原因。

### 2.8 命名与词序：把「不可推」的部分明确交出去

城市 / 河流 / 神 / 氏族四种名字，语义按地形与天象取：
河口用「水+口」、山口用「山+门」、潮线用「潮+线」；神名绑 `sky_phenomena[0]`。

**词序（主宾动 vs 主动宾）推不出来。** 它不是地理决定的，也不是能量决定的。
引擎给两个候选、标 `source: "不可由物理推出"`，让作者选。
这条写进「不做什么」，比假装能推更可信。

## 3. 接触 · 多文明（`contact`）

### 3.1 缺口

`chronicle` 的 `H10 争地` 与 `H11 大疫` 各只有一条，且**没有对手、没有路线**。
「一群人和另一群人打了一仗」这句话，在没有第二群人的世界里是空的。

### 3.2 立场：只算「必然会接触」，不算「谁赢了」

明确拒绝 civ-atlas 那种「每个势力有性格与目标、互相触发」的模型——
那个模型能长出好故事，但**不可复算**：同一份存档换一版权重就是另一段史。

盘古的做法是：**只算「必然发生的接触」，不算「谁赢了」。**

### 3.3 成本场：用地图的真实字段

从 `MapResult` 直接取：`elev` / `biome` / `river` / `discharge` / `ocean` / `habitat`；
风用 `mapgen._wind_field(cfg, lat, lon, ux, uy, uz)` **现算**（解析式，不必给 `MapResult` 加字段）。

```
陆路（每格）：
  slope    = |∇elev|  (m/m，格距 111 km 差分)
  v_walk   = 4.5 km/h / (1 + 3·slope) × biome_f
  biome_f  = 草原 1.0 / 森林 0.7 / 荒漠 0.4 / 冰原 0.2 / 湿地 0.5
  river    = 有河 → v_walk × 1.6（顺流）/ × 1.1（逆流，按 discharge 方向判）

海路（每格）：
  (u, v)   = _wind_field(...)        # 注意：这是**归一化方向**，|W| ≈ 1，不是 m/s
  W_ms     = |(u, v)| · wind_ref_ms  # wind_ref_ms 默认 8 m/s，可被 climate.wind_ref_ms 覆盖
  θ        = 航向与风向的夹角
  v_ship   = (2.0 + 1.2·W_ms·cosθ) km/h，下限 1.2 km/h
  → 顺风 11–12 km/h（约 6 节），逆风 2 km/h
```

**有向图，不是无向图。** 顺风 7 天、逆风 60 天是真实存在的（季风世界的全部历史都建在这上面）。
边权取 `min(t_ab, t_ba)` 用于分类（「他们见过面」），`max` 用于「谁先到」（「谁打过来」）。

**潮汐锁定的世界没有纬向风带。** `_wind_field` 里有一个 `cfg["locked"]` 分支：
风向是「从亚恒星点向四周吹散」的放射状场（`mapgen.py:617-634`）。
所以接触图在这种世界上会变成**以晨昏线为圆心的放射状**，
「沿纬度东西向航行」这件事根本不存在——这一支必须走代码里现成的分支，不能套纬向公式。
赫利孔（倾角 18°、未锁定）走常规分支；写测试时两个世界都要跑。

禁区：`|lat| > 75°` → `cost = ∞`（极地冰盖，可穿越但没有补给）；
`slope > 0.15` 且无河谷 → `×10`（不是 ∞：翻山是可能的，只是慢）。

### 3.4 聚落：不是均匀撒点

```
N        = clamp(round(4 + 12·land_fraction), 4, 16)      # 赫利孔 0.224 → 7
权重     = habitat × (1 + 0.5·有河) × (1 + 0.3·沿海)
选中     = 贪心 k-center：每次取「离已选点最远的高权重格」，最小间距 400 km
人口     = P_total · i^(−1.0) / Σ j^(−1.0)                # Zipf，[经验]
```

`P_total` 从 `carrying_capacity.humans_subsistence` 读，**不另造**——
这样 `contact` 与 `chronicle` 的人口数字天生一致（否则两处会各给一个人口，读者一眼看出矛盾）。

### 3.5 接触类型：天数定性质，附一条物理判据

| 成本（天，单程） | 类型 | 带什么 | 频率 |
|---|---|---|---|
| < 10 | 常年贸易 | 货物、借词、**病原** | 每年 |
| 10–40 | 季节性 | 朝贡、劫掠、传教 | 十年一遇 |
| 40–120 | 传说级 | 神话与二手货 | 一代一次 |
| > 120 | 无接触 | 「海的另一边」是空白 | — |

**病原那一条要算，不能拍。** 病原体外存活时间 `[经验]`：

```
τ_pathogen = 3 d · exp(−(T − 288)/12) · f_humidity
f_humidity = 1.0（有海/湖 500 km 内）｜0.6（内陆）｜0.3（荒漠）

传播条件：τ_pathogen > 行程天数(cost_days)
```

于是：**湿热的海上贸易网是疫病的高速公路；干燥内陆的商队走 40 天，病死在半路。**
`H11 大疫` 的年份因此可以被检查：它的路线必须是一条 `τ_pathogen > cost_days` 的边。

### 3.6 与 `chronicle` 对齐：用 `t_year`，不要另造年号

`chronicle` 的事件已经带 `t_year`（自「第一笔」起的年数）与 `q`。
接触边的出现时刻：

```
since_year(edge) = max(t_year(H08 出海), 两端城邦的建城年) + ceil(cost_days / 365.25)
```

两端建城年取 `H06 第一批城市` 的 `t_year`（同一份史，不打折）。
于是「第 12,400 年，三个城邦第一次在同一张桌子上」是可算的：
它是 `max(出海年, 建城年) + 航程年`，不是作者挑的一个数。

`H10 争地` 的对手：只在 `cost < 40 天` 的边上取「最近的邻居」；
`H11 大疫` 的路线：沿 `τ_pathogen` 判据的边。
两条事件因此从「一句话」变成「一条边」——**这是 `contact` 存在的主要理由**。

### 3.7 借词：要过音系适配

`loanwords` 不能直接抄邻居的词形（两边音系不同）。做法是**音段距离最近替换**：

```
dist(a, b) = 特征汉明距离（浊/送气/部位/方法/响度 五维）
loan → 把表外音逐个替换为 min dist 的表内音；不合配列则加元音
```

于是「借词」本身是一条证据：读者能看出这个词来自另一套口音，
而不是「作者从同一个池子里抽了两次」。`C02` 因此升级为
「借词必须出现在 `lexicon.words` **且** 能在本世界音系下完整切分」。

| C03 | 边数 ≥ N−1 且 ≤ 2N（MST + 冗余边，不许退化成完全图） |
| C04 | `H10` / `H11` 若存在，必须落在某条接触边上（`H11` 还要求 `pathogen_ok`） |
| C05 | `|lat| > 75°` 的成本为 ∞（极地不可穿越） |
| C06 | 每条边都有 `cost_days` 与 `cost_days_rev`，且 `max/min ≤ 30`（否则判为数据错误） |
| C07 | `since_year ≥ max(出海年, 建城年)`，且与 `chronicle` 的 `t_year` 同源 |

C06 是**数据自检**：真实世界顺逆风差异可以到 5–10 倍，
但 30 倍以上说明风向或航向算错了（比如把纬向风当成了经向）。

### 3.11 会翻车的地方

| 症状 | 原因 | 对策 |
|---|---|---|
| 完全图（每城和每城都有边） | 阈值太宽 | MST + 一条冗余边；C03 硬门槛 |
| 岛国与世界其余部分断开 | 海路成本算成了 ∞ | 海路只在「无风且无流」时高惩罚，不是 ∞ |
| 所有边都从西向东 | 只用了纬向风 | 用 `_wind_field` 的 u/v 两分量 + 航向点积 |
| 潮汐锁定世界算不出海路 | 套了纬向风公式，而那里根本没有纬向风带 | 走 `cfg["locked"]` 分支（放射状风场） |
| 船速只有 3 km/h，整个世界都是孤岛 | 忘了 `_wind_field` 返回的是**归一化方向**（\|W\|≈1），没乘 `wind_ref_ms` | §3.3 第一步就 ×8 m/s |
| 疫病每条边都能传 | 没算存活时间 | C04 的 `pathogen_ok` |
| 人口与编年对不上 | 另算了一个 `P_total` | §3.4：只读 `carrying_capacity` |
| 只有一个聚落时崩 | `N=1`，没有边 | `N < 2` 直接 skip 并注明「这个世界还没有第二个城」 |

### 3.12 不做什么

- 不做势力 AI、外交博弈、战争过程、条约与王朝更替
- 不做经济模型（货物只记名字与来源，不记数量与价格）
- 不做「玩家干预」（那是编辑器的事）
- 不做真正的洋流环流（`ocean_heat_transport` 只是标量，记进限制）

### 3.13 工作量

约 480 行：成本场 140、聚落 70、图与 MST 80、类型与病原 60、
借词适配 60、对齐与验收 70。依赖 `lexicon`（借词）与 `chronicle`（时刻）。

## 4. 三个方向的关系

```
        深渊 geohistory ──┐
        （独立，最重）      │  给地形一个来历
                          ▼
   律 → 地 → 天 → 账 → 史 → 名 → 交 → 问 → 艺
                        ▲     ▲    ▲
                    chronicle  │    │
                               │    │
              舌 lexicon ──────┘    │  给东西起名
              （独立，最轻）         │
                                     │
              接触 contact ──────────┘  让名字相遇
              （依赖上面两个）
```

链条到头是 `inquiry` 与 `aesthetic`：**两个文明接触之后，问学层会多出「他们怎么解释对方的语言」
这一类假说，艺术层会多出借来的调式与纹样。** 这不是新增层，是已有两层多了一条输入
（`contact` 写进 `history.contact`，问学与艺术各读一条边）。

**建议节奏**：

| 阶段 | 内容 | 理由 |
|---|---|---|
| 1.1.6a | `lexicon` | 独立、最快出效果，且顺手修掉 `naming` 的「slug 音系」 |
| 1.1.6b | `contact` | 依赖 `lexicon` 的借词与 `chronicle` 的时刻 |
| 1.1.6c | `geohistory` | 独立但最重，可延到 1.1.7 |

如果只能做一个：**做 `lexicon`**。它投入产出比最高，且是「名字最难伪造」的唯一解法；
它还顺手把 `naming` 从「slug 回声」升级成「物理音系」。

## 7. 三条共同约束

1. **每条输出都必须带 `src`**。答不出「凭哪个字段推得」的句子，不许出现在引擎的输出里。
   这条规矩在 `ca`（`source`）、`entail`（`src`）、`chronicle`（`src`）、`inquiry`（`src`）、
   `aesthetic`（`src`）上已经立了五次，第六到第八次也不能破例。
2. **同 seed 可复算**，`--check` 对 hash。三层各自一个 hash，互不污染。
3. **每个方向都要有一份「不做什么」清单**。盘古的失败模式不是做得少，而是**膨胀成一个模拟器**：
   一旦开始模拟「谁赢了」，它就既不可复算也不可证伪，也就不再是盘古。

## 8. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 深渊的计算量 | 64,800 格 × 5 亿年若真平流会跑不完 | 只追板块多边形（~320 顶点），不追格子 |
| 板块面积漂移 | G02 永远不过（Voronoi 固有） | §1.4 方案 A：旋转多边形 |
| CO₂ 显式欧拉发散 | 一步跳到负值 | §1.7 指数积分，`dt = τ` |
| 末帧与地图对不上 | 两处各算一次海平面 | 水量只从 `ledger` 读，海平面只走 `_solve_sea` |
| 语言「像不像真的」无法客观验收 | 只能靠结构约束（L03/L06） | 接受这一点：语言是给人读的，不是给机器验的 |
| `lexicon` 与 `naming` 两套音系 | 同一个世界两个口音 | §2.2 接管 + L05 硬门槛 |
| 接触退化成完全图 | 每城和每城都有边，等于没算 | MST + 一条冗余边；C03 是硬门槛 |
| 接触只算出「顺风单行道」 | 只用纬向风 | 用 `_wind_field` 的 u/v + 航向点积；C06 查 30 倍上限 |
| 三个方向一起做会拖长 1.1.6 | 版本迟迟不发 | 按 a/b/c 拆，每一段都能独立交付 |
| `ocean_heat_transport` 只是标量 | 海路成本不准 | 记为已知限制，等 2.0 的洋流环流 |
