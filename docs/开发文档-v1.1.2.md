# 盘古 1.1.2 · 调参层（开发文档）

> 1.1.1 让世界有了「地」，1.1.2 让**改动**可验证：改一个数、扫它的连续谱、和上一版对比。
> 本文记录 1.1.2 的范围、数据契约、算法、判定标准与验收。面向维护者；第一次用盘古的人读 `SKILL.md`。

---

## 1. 范围

1.1.2 只做一件事：把「改设定」从手工劳动变成可复算的操作。拆成四个可独立验收的能力：

| # | 能力 | 命令 | 解决什么 |
|---|---|---|---|
| 1 | 定点改 / 增 / 查 | `patch` | 手改 JSON 会漏改派生量、忘升版本、写错层级 |
| 2 | 参数敏感度扫描 | `sweep` | 只能看到「选了一个值」，看不到邻近值会怎样 |
| 3 | 版本对比 | `diff` | 不知道这版改了什么、哪些产物已经过期 |
| 4 | 代价二次索引 + 反常识度 | `axioms --cost` / `validate` | 按学科找不到「我想要的代价」；不知道改多改少的边界 |

不做：二维相图、自动回滚、schema 迁移、把派生量自动改写成自洽解（最后一条只做观察，不做写入）。

---

## 2. 设计约束（不能破的）

| 约束 | 含义 | 为什么 |
|---|---|---|
| **单一数据源** | 只改 `world.json`；`preview.html` / 世界档案 / 地图都是派生文件 | 手改生成物会让多方漂移 |
| **路径文法同源** | `world_schema.parse_path()` 是唯一解析器，`patch/sweep/diff` 与切片 `cites`、红队 `target`、CA `source` 共用 | 两套路径文法迟早对不上 |
| **不静默写入** | `patch` 默认拒绝不存在的字段；`sweep` / `diff` 绝不写盘 | 调参工具最怕「悄悄多出一个字段」 |
| **不改变评分基线** | 反常识度只进派生量，不新增 `Check` | 1.1.1 的 100 分世界不该因为换版本掉分 |
| **判定写死** | 「崩」= fatal 高于基线，或总分低于基线 3 分 | 阈值可讨论，但不能每次运行都变 |

## 3. 数据契约

### 3.1 `history.revisions[]` 新增可选字段

```jsonc
{
  "version": "1.1.2",                // 与 meta.version 同步
  "date": "2026-11-01",
  "change": "patch：cosmology.bodies[0].albedo=0.42",
  "fields": ["cosmology.bodies[0].albedo"]   // 1.1.2 新增，可选，最多 40 条
}
```

`fields` 缺失不影响任何旧世界；`patch --no-bump` 时不写修订。

### 3.2 `derived.weirdness`（只出现在报告里，不落盘）

```jsonc
{
  "score": 48,
  "band": [40, 70],
  "label": "推荐区间",
  "items": [
    {"name": "常数改写", "points": 8, "detail": "G=0.6×"},
    {"name": "另类生化", "points": 12, "detail": "能量货币：硫铁簇；遗传载体：六碱基核酸（HNA）"}
  ]
}
```

### 3.3 公理库条目新增 `cost_tags`

```jsonc
{"id": "P01", "name": "斥力宇宙", "cost_tags": ["空间", "物质", "结构"]}
```

标签来自 `COST_TAGS` 的关键词映射（八类），不要求作者逐条手写，但允许后续改成显式字段。

## 4. 算法

### 4.1 点路径写入（`world_tuning.set_value`）

1. `ws.parse_path` 把 `a.b[0].c` 拆成 `['a','b',0,'c']`。
2. 逐段下行。遇到下标：容器必须是数组，`index == len` 仅在 `create=True` 时允许追加。
3. 遇到键：容器必须是对象；键不存在时，`create=False` 直接失败，`create=True` 按下一段类型建 `{}` 或 `[]`。
4. 最后一段写值；返回旧值与该键是否存在（用于区分「改」与「增」）。

值解析顺序：`json.loads` → 失败当字符串。因此 `4.0e-11` / `true` / `null` / `[1,2]` / `"文本"` 都能写，`水` 这类裸文本会落成 `"水"`。

### 4.2 版本推进（`bump_version`）

- 三段且补丁位非零：`1.1.1 → 1.1.2`
- 否则次版本 +1：`1.0 → 1.1`
- 无数字：回落 `1.0`

理由：SKILL 的「+0.1」在三段版本上落到补丁位，避免改一个字就把世界升成 2.0。

### 4.3 敏感度扫描（`sweep_world`）

```text
base = validate(deepcopy(world))
for v in values:
    w = deepcopy(world); set_value(w, param, v)
    if recalc: recalc_bodies(w)      # 全体天体：密度 / 重力 / 半径 km
    rep = validate(w)
    broken = rep.fatal > base.fatal or rep.score <= base.score - 3
```

输出安全窗（未被判崩的取值区间）与第一个崩点。`--recalc` 的必要性：P01 比较的是**声明值**与推算值，扫质量/半径/G 时若不同步重算声明值，所有非基线点都会因为「声明不一致」被判 fatal，曲线失去意义。

`recalc_bodies` 只改三个地球对照值，不改物理设定：

```text
density_gcc = M × 5.514 / R³
gravity_g   = M / R² × (G'/G)
radius_km   = R × 6371
```

### 4.4 版本对比（`diff_worlds`）

- 对象 → 键并集递归；`planet_map.coarse` 视为不透明块，只比是否相等。
- 等长短数组 → 逐项递归（`physics.constants` 要看清单条常数）。
- 不等长短对象数组 → 共同前缀递归，多出的项记为新增/删除（`history.revisions`）。
- 其余数组 → 整体比，报规模。
- 改动超过 `limit`（默认 200）置 `truncated`，不静默截断。

派生量对比走 `validate(deepcopy(world))` 两次，避免校验就地写 `consistency.score` 污染数据。

### 4.5 反常识度（`weirdness`）

| 维度 | 计分 | 上限 |
|---|---|---|
| 常数改写 | 每处 8（与地球值偏离 >0.1%） | 32 |
| 新相互作用 | 每项 6 | 18 |
| 定律偏离 | 每条 4（`deviation` 不以「标准/未改/完整保留」开头） | 16 |
| 守恒破缺 | 每条 8（`broken_symmetries`） | 16 |
| 另类生化 | 每项 6（能量货币 / 遗传载体名不含 ATP/DNA/碳基/水基） | 12 |
| 时空尺度 | 每项 6（日长偏离 24h >10%、年长偏离 365.25d >10%、重力偏离 1g >10%） | 18 |
| 天体构型 | 每项 6（无恒星 / 双星 / ≥3 星 / ≥2 行星） | 12 |

合计封顶 100，与推荐带 40–70 比较。这是**信息量指标**：分数高不代表好，只代表偏离多。

## 6. 已知限制

- `patch` 不做派生量联动：改 `mass_earth` 后 `density_gcc` / `gravity_g` 仍是旧值，`validate` 会报 P01。这是故意的——要不要改声明、改成多少，是设定决策，不是工具决策。
- `sweep` 只支持数值标量；一维扫描看不到两参数联动。
- `diff` 的 `planet_map.coarse` 整体比，看不出单个格子变化（本来也不该手改）。
- 反常识度是启发式关键词 + 计数，不理解语义；戏剧性强的世界可能分值不高。

## 7. 后续方向

1. **二维相图**：`sweep --param2`，输出 ASCII 热力网格（评分 / fatal 双通道）。
2. **自洽解建议**：`patch --suggest-recalc` 给出「若改质量，密度应为 X」的建议值，仍需人工确认。
3. **失败案例库**：把「改到崩溃」的中间态存进 `examples/_fails/`，供学习怎么修。
