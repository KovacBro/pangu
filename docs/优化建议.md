# 优化建议

> 1.0 已经把主干跑通。以下是按"投入产出比"排序的 12 条改进方向，以及 1.0 遗留的技术债。

---

## 一、创作质量（最该先做）

### 1. 第一人称切片：用 200 字验尸 ★★★★★

**问题**：`world.json` 可以 100 分，但读起来仍然是"参数表"，不是"世界"。

**做法**：第 7 斧增加一道强制关卡——用 200 字写「一个普通居民的一天」，从睁眼写到入睡。写不出来，或写出来像说明书，说明设定没有落地到感官层。

**为什么有效**：这是最便宜的照妖镜。它能一次性暴露"这个世界的重力和建筑高度不匹配""他们的一天 31 小时但作息按 24 小时写"这类机检抓不到的漏洞。

**验收**：切片里必须出现至少两个 `sky_phenomena`，且不能出现任何 `physics` 未支持的现象。

---

### 2. 红队审查：让 AI 扮演敌对物理学家 ★★★★★

**问题**：自己审自己，必然放水。`validate` 只能抓数值矛盾，抓不到"这个解释太敷衍"。

**做法**：审查阶段拆成两个角色——**红队**（只负责攻击，生成 5 条最尖锐的质疑，不许给方案）与**盘古**（逐条回应）。红队 prompt 要点：

```
你是一位来自地球的行星科学家，任务是证明这个世界不可能存在。
只准提问，不准建议。每条质疑必须指向一个具体的数值或机制。
```

**为什么有效**：把"找漏洞"和"补漏洞"分离，能逼出真问题。1.0 的 `consistency.checks` 是自查，2.0 应该引入对抗。

---

### 3. 公理库按「代价类型」二次索引 ★★★★

**问题**：现在按学科索引（物理 / 生物 / 化学）。但创作时的真实需求是**"我想要某种代价"**——比如"我想让这个世界的人短命""我想让远行变得不可能"。

**做法**：给 62 条积木加第二套标签：

| 代价类型 | 对应积木 |
|---|---|
| 寿命 / 时间 | C10、B08、B09、P02 |
| 空间 / 距离 | M01、M02、C08、C09 |
| 感知 / 认知 | M03、M08、B06 |
| 能量 / 物质 | P06、K01、K04 |
| 社会 / 权力 | V05、V06、B07 |

命令加 `axioms --cost 空间`。

---

### 4. 敏感度扫描：看见参数的连续谱 ★★★★

**问题**：现在是"选一个值"（G' = 0.60），看不到邻近值会怎样。而**世界的形态其实是连续的**。

**做法**：新增子命令 `sweep`：

```bash
python scripts/pangu.py sweep world.json --param "physics.constants[0].world_value" \
       --from 3.5e-11 --to 4.5e-11 --steps 6
```

输出一张表：每个取值下的表面重力、逃逸速度、能否撑住 3 R⊕、平衡温度、评分。用户能直观看到"G 再小一点，这世界就散了"的临界点。

**为什么有效**：临界点本身就是最好的设定素材——"他们的世界刚好在崩溃边缘"比"他们的世界很稳定"有戏得多。

---

### 5. 反常识度指数 ★★★

**问题**：改太少 = 换皮，改太多 = 噪声。但没人知道"多少算合适"。

**做法**：算一个 0–100 的偏离度：

```
偏离度 = 35×改动常数数 + 25×改写定律数 + 20×新增维度数 + 20×废除守恒律数
```

推荐区间 **40–70**。低于 40 提示"仍是地球换皮"，高于 70 提示"设定已超出可理解范围，读者会放弃"。

---

### 6. 失败案例库 ★★★

**问题**：现在的示例只有成功案例（100 分）。但学习价值最高的是**怎么修**。

**做法**：建 `examples/_fails/`，收录被判 fatal 的世界，附审查报告与修补前后对比。例如：

- `super-earth-no-g.json`：3 R⊕ + 1 G，P01 fatal → 修补为 G'=0.6 → 打分从 42 到 100
- `binary-too-close.json`：行星 1.2 AU / 双星间距 1 AU，P03 fatal → 压缩双星间距

---

## 二、3D 表现

### 7. 地面第一人称：站在地表看两个太阳 ★★★★★

**问题**：现在只能从太空看。而"双日双影"这个设定最强的说服瞬间，是**站在地上抬头**。

**做法**：加第四个视图 `surface`。用半球天空穹顶 + 地平线剪影，两颗太阳按真实方位角与高度角移动，投出两道方向不同的影子（用简单的投影贴花或第二个定向阴影）。

**为什么值**：这是整个技能从"设定文档"变成"体验"的那一步。技术难度中等（一个半球 + 两个方向光 + 地表平面），收益极高。

---

### 8. 季节与倾角演示 ★★★

`axial_tilt_deg` 目前只是数据。让它在 3D 里驱动光照倾角随公转变化，用户就能看见"这个世界的夏天有多长"。顺带能验证 `calendar` 是否说得通。

---

### 9. 世界预告片导出 ★★★

`preview.html` 加一个"录制 12 秒"按钮，用 `MediaRecorder` + `canvas.captureStream` 导出 webm。世界需要能发给别人看的东西。

---

## 三、工程与协作

### 10. 与「世界观构建」自动串联 ★★★★

盘古跑完第 5 斧后，自动生成下游的 `regions` 骨架：按 `biomes` 生成地区名、按 `sky_phenomena` 生成节庆、按 `calendar` 生成纪元表。省掉用户的重复劳动，也让两个技能的数据模型真正咬合。

**注意**：必须保持"盘古是上游"的方向，不能反向污染物理层。

---

### 11. 世界版本 diff ★★★

`meta.version` 每 +0.1 都应该能对比。新增 `pangu.py diff a.json b.json`，输出：

- 数值变更表（G：0.60 → 0.58）
- 受影响的派生量（表面重力 1.76 → 1.70）
- 需要重跑的下游产物（preview / 档案 / 审查报告）
- 新增的自洽冲突（如果有）

---

### 12. 语言生成：让命名长在物理上 ★★

无上下方向的世界（壳世界、环世界）不该有"高 / 低"这类词；永夜世界的语言不该有"日出"作比喻。给 `civilization` 加一个 `lexicon` 字段，由物理约束反推词汇缺口，再生成对应的替代隐喻（如"离轴 / 向轴"）。

这一条做扎实了，世界会突然变得可信——因为**语言是最难伪造的证据**。

## 四、1.0 已知技术债

| # | 项 | 影响 | 建议 |
|---|---|---|---|
| 1 | 平衡温度忽略温室 | 表面温度可能低估 30–50 K | 加 `greenhouse_delta` 字段，允许手动补偿 |
| 2 | 轨道用圆近似 | 偏心轨道（如远灯 e=0.18）在 3D 里画成圆 | 用 `EllipseCurve` 按 e 与近点幅角绘制 |

| 5 | 群系上限 8 | 复杂世界会被截断（`validate` 有 warn） | 改为纹理图集或分段着色器 |

1. **第一人称切片**（第 1 条）— 成本最低，暴露问题最多
2. **地面视角 3D**（第 7 条）— 把设定变成体验的唯一路径

## 六、跨 harness（1.0 之后的新增方向）

1.0 已把"能力"与"加载方式"拆开：核心只有一份，入口可以有很多个。下面是在这个基础上的进一步改进。

### 13. 自动探测宿主并安装 ★★★★

`install.py` 现在要求用户自己说装到哪。更好的做法是探测：

```bash
python install.py --auto     # 扫 ~/.claude/skills、./.cursor、./.windsurf、GEMINI.md、~/.codex
```

扫到了就问一句"检测到 Cursor，要装吗"，扫不到才让人工指定。降低首次使用门槛，尤其是不知道自己是"哪种 harness"的用户。

### 14. 安装完整性自检 ★★★★

用户装完常常不知道有没有装对。加一条：

```bash
python install.py --verify --dest .
```

检查四件事：指针文件是否存在、`{{PANGU_ROOT}}` 是否已替换、指向的 `SKILL.md` 是否真实存在、CLI 能否 `doctor` 通过。任何一项失败给出可执行的修复命令。**这是把"排错表"变成"自动体检"**。

### 15. 英文版正文 ★★★★

当前 `SKILL.md` 全中文。对英文模型（以及英文 query 的用户）来说，`description` 的触发匹配会明显变弱——用户说 "build a world with two suns" 时，中文 description 的语义相似度可能不够。

建议：`SKILL.md` 保持中文（这是方法与语感的载体，翻译会掉东西），但**增加 `description_en` 与一份 `references/en/quickstart.md`**，并在 frontmatter 的 `description` 里混入英文关键词。收益是中英双语检索都能命中，成本很低。

### 16. 控制 SKILL.md 体积 ★★★

正文约 200 行，对 8k–32k 上下文的宿主已经偏重；若再叠加 `references/`，小上下文模型会挤掉用户的实际需求。

建议把正文压到"决策必需"的最小集（三律 + 七斧表 + 命令速查 + 质量红线），把"为什么"与展开案例移到 `references/`。**渐进披露的收益在于：加载少而准，而不是加载全。**

### 17. MCP 补 resources 与 prompts ★★★

现在 MCP 只有 tools。补上：

- `resources`：把 `world.json`、世界档案、审查报告以 `pangu://world/<id>` 形式暴露，客户端可做只读浏览
- `prompts`：把"造一个新世界""验尸这份设定"做成 prompt 模板，用户一键触发

这会让 MCP 路径从"能调工具"升级为"能带上下文进入"。

### 18. 路径含中文的兼容性 ★★★

工程放在 `E:\skills\盘古`，Windows 上已出现过长路径与编码相关的小摩擦（递归复制那次就撞上了 `WinError 206`）。

建议：**安装目标默认用 ASCII 目录名**（`pangu`），并在 README 首屏提醒"技能源路径避免非 ASCII"。同时给 `install.py` 加一层保护：目标路径含非 ASCII 时打印 warning（不是错误，只提醒某些工具链可能出问题）。

### 19. 无 Python 宿主 ★★

部分沙箱/移动端 agent 跑不了 Python。可以做一个**纯 JS 版校验器**（把 `world_schema.validate` 的 17 项机检移植到浏览器/Node），配合 `preview.html` 里的同一份 JSON，让 3D 页自带"体检"按钮。属于 2.0 方向，但技术上可行且体验加分。
