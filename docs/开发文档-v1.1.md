### 1.2 本机环境备注（踩过的坑，先看这条能省半小时）

  ```powershell
  $env:TEMP='E:\大肥鱼\work\tmp'; $env:TMP=$env:TEMP
  python scripts/selftest.py
  ```

- PowerShell 5.1 往 python 传中文参数会变 `?`：一律用 ASCII 相对路径，中文只放 json/md。
- **预览页必须在 HTTP 下看**：`file://` 打开时 `import` 本地 `three.module.js` 会被浏览器的 ES module CORS 拦掉，页面降级成数据视图（看起来像 3D 坏了，其实没坏）。截图前先 `python -m http.server`。

## 4. 功能 A · 第一人称切片（两百字验尸）

### 4.1 要解决什么

100 分的 `world.json` 仍然可以是「参数表」。切片是最便宜的照妖镜：写不出「一个普通居民从睁眼到入睡」，说明设定没落地到感官层。

### 4.2 数据结构（新增，可选）

```json
"narrative": {
  "three_seconds": "…",
  "setpiece": "…",
  "hook": "…",
  "slice": {
    "text": "（180–260 字，第一人称，从睁眼写到入睡）",
    "cites": ["cosmology.sky_phenomena[0]", "cosmology.calendar.day_hours", "biology.energy_currency"],
    "hours": [0.0, 31.4],
    "status": "draft | ok"
  }
}
```

- `text`：**180–260 个汉字**（按去标点后的字符数算）。
- `cites`：切片里引用的真实字段路径（点路径 + 可选下标），**必须能在 world.json 里解析到**。
- `hours`：切片覆盖的时间范围（从第几小时到第几小时），必须落在 `calendar.day_hours` 之内。
- `status`：`draft` 时只 warn；交付（`--strict`）时必须是 `ok`。

### 4.3 CLI

```bash
python scripts/pangu.py slice examples/helikon/world.json --check
# → 切片体检：字数 214 ✓ ｜ 引用 3 条全部解析 ✓ ｜ 现象 2/2 在册 ✓ ｜ 时序 0–31.4h ✓ ｜ 结论：可交付
```

`slice --check` 只做机检，不生成文本。生成文本由 agent 按 `references/七斧创世法.md` 的「第 7 斧 · 落地」写，写进 `world.json`，再跑 `--check`。

### 4.4 校验项（新增，进 validate）

| ID | 规则 | 级别 |
|---|---|---|
| **N03** | `narrative.slice.text` 存在且字数 180–260 | warn（缺）/ error（`--strict`） |
| **N04** | `slice.cites` 每条都能在 world.json 解析出值 | warn |
| **N05** | 切片里出现了 ≥2 个 `cosmology.sky_phenomena` 里的现象名 | warn |
| **N06** | 切片里出现的「小时/天数」与 `calendar.day_hours`/`year_days` 对得上（容差 ±15%） | warn |

> 注意：N05 靠字符串匹配就要容忍同义词（「双影」vs「两道影子」）。做法：`sky_phenomena[]` 每项允许别名，schema 里加 `sky_phenomena_aliases: { "双影": ["两道影子", "两个影子"] }`。

### 4.5 反例（写进 references，别只写在文档里）

- ❌「这里的人生活很辛苦」——没有可观测细节。
- ❌ 切片里出现 `physics` 没支持的现象（比如「重力忽大忽小」但 `physics.constants` 里没有对应机制）。
- ❌ 31.4 小时的白天，作息却按 24 小时写（典型漏检，N06 就是抓这个）。

### 4.6 验收

- `examples/helikon` 补一段 200 字切片（作者本人写，或按 §4.3 生成后人工改），`slice --check` 全绿。
- `selftest` 新增 E8：切片检查能抓出「字数不足」「引用不存在」两个反例。

## 5. 功能 B · 地面视角（站在地表看两个太阳）

### 5.1 要解决什么

现在只有「系统 / 天体 / 远景」三个太空视图。双日双影、44 天一次的双星合、钴蓝黄昏 —— 这些痕迹律的东西**必须站在地上才成立**。这是从「设定文档」到「体验」的那一步。

### 5.2 数据需求（先补 schema，再画）

```json
"cosmology": {
  "surface": {
    "observer": { "lat_deg": 12.0, "lon_deg": 0.0, "elev_m": 300 },
    "horizon_deg": 0.0,
    "ground_color": "#2a3a4a",
    "notes": "观察点在哪、海拔多少"
  }
}
```

- `observer` 可选；缺省时取 `lat_deg=0`（赤道）并在页面上标注「默认观察点」。
- 行星自转/公转参数从 `bodies[]` 里拿：`rotation_hours`、`orbit.period_days`、`axial_tilt_deg`、`orbit.eccentricity`（1.0 已有）。
- **恒星方位角需要相位**：1.0 的 `orbit` 只有 `parent / a_au / eccentricity / inclination_deg / period_days`，没有相位。1.1 新增可选 `orbit.phase_deg`（默认 0），地面视角用它算「此刻两颗太阳在哪」。

### 5.3 实现要点（`preview_template.html`）

1. **新视图 `surface`**：加按钮 `v-surface`（与 `v-sys/v-body/v-far` 同排），状态机沿用现有 `setView` 思路。
2. **场景构成**：
   - 半球天穹（`SphereGeometry` 半个 + `BackSide`），按 `sky_color`/时间做渐变色；
   - 地面平面（大圆盘）＋ 地平线剪影（程序生成的丘陵线，别用外部模型）；
   - 星星点阵（`Points`），亮度按天空亮度衰减；
   - 每个恒星画成 sprite；位置由**方位角/高度角**算，不是随便摆。
3. **天文计算（必须写在 JS 里，零依赖）**：
   - 恒星从行星看去的方位角 = 相位角（由 `orbit.phase_deg` + 时间推进得）；
   - 高度角 = 90° − 天顶距，天顶距由观察点纬度、赤纬（近似取 0，或由倾角推）、时角算；
   - 潮汐锁定行星：恒星固定不动，改成「太阳悬在固定方位」，昼夜由自转驱动 —— 特殊分支要写。
4. **两道影子**：
   - 地面平面画两块「影子贴花」（低透明度多边形），方向 = 各恒星方位角 +180°；
   - 影长 = 高度 × tan(天顶距)；高度角 < 5° 时用超长影子（钳制上限，别撑爆画面）。
   - 两道光颜色不同（长明偏白、短烛偏琥珀），**影子边缘一锐一糊**（1.0 的 `sky_phenomena` 里赫利孔就是这么写的）。
5. **季节**：`axial_tilt_deg` 驱动一年内太阳高度角曲线的整体偏移；给一个「一年快进」按钮，让「一年 357 天」看得见。
6. **降级**：没有恒星 / 没有 `surface` / WebGL 不可用时，隐藏该按钮并给一句原因，不要白屏。

### 5.4 校验项（新增）

| ID | 规则 | 级别 |
|---|---|---|
| **O03** | `cosmology.surface.observer` 纬度在 −90..90、经度 −180..180 | warn |
| **O04** | 恒星数量 ≥1 且 `surface` 不指向不存在的恒星 id | warn |

### 5.5 验收

- 赫利孔：地面视图能看到两颗太阳，影子方向夹角 ≈ 30–60°（跟双星相位有关），双星合那一分钟两影几乎重叠。
- 截图入 `examples/helikon/surface.png`，用于文档与宣传。
- `selftest` 新增 E9：生成的 HTML 含 `v-surface`、含 `surface` 数据注入、无残留占位符。

## 6. 功能 C · 红队审查（让 AI 扮演敌对物理学家）

### 6.1 要解决什么

1.0 的 `consistency.checks` 是自查，自己审自己一定放水。红队只负责攻击、不给方案，逼出真问题。

### 6.2 数据结构

```json
"consistency": {
  "score": 100,
  "checks": [ … ],
  "redteam": [
    {
      "id": "RT01",
      "q": "G′=0.60G 下 3R⊕ 的逃逸速度只有 33 km/s，大气如何留住？给一个数量级。",
      "target": "physics.constants[0].world_value",
      "verdict": "answered",          // open | answered | accepted | rejected
      "answer": "…（我的回应，引用具体字段）",
      "fix": "cosmology.bodies[0].atmosphere.greenhouse_delta_k=35" // 可选：如果接受质疑要改的字段
    }
  ]
}
```

- `target` 必须是能在 `world.json` 里解析到的点路径 —— **这是红队和「空口挑刺」的分界线**。
- `verdict` 四态：`open`（还没答）/ `answered`（答了）/ `accepted`（接受并改）/ `rejected`（拒绝且说明理由）。
- 交付时不允许有 `open`。

### 6.3 CLI

```bash
# 1) 生成 5 条质疑（只读 world.json，输出 JSON 到 stdout，不写文件）
python scripts/pangu.py redteam world.json --count 5 --format json

# 2) 把回应写回 world.json（幂等，按 id 覆盖）
python scripts/pangu.py redteam world.json --answer RT01=answered --text "……" --fix "physics.constants[0].greenhouse_delta_k=35"

# 3) 体检
python scripts/pangu.py redteam world.json --check
# → 5 条 / 目标可解析 5 / open 0 / 结论：可交付
```

**质疑的生成策略**（零依赖、不许联网）：读 `consistency` 与派生量，按模板库轮询，每条必须挂到具体字段：

| 模板 | 打哪 | 例子 |
|---|---|---|
| 数量级 | 派生量字段 | 「表面重力 1.76 g 下，3R⊕ 地壳的屈服强度够吗？给数量级。」 |
| 能量收支 | `biology`/`civilization` | 「总光度 1.468 L☉ 摊到 26.4 M⊕，人均可用功率是多少？」 |
| 观测一致性 | `sky_phenomena`/`calendar` | 「44 天潮汐周期，怎么从地面观测一次『双星合』？时刻表能预报吗？」 |
| 边界条件 | `atmosphere` | 「气压 68 kPa，两倍地球半径的高原上还够呼吸吗？」 |
| 反例 | `mathematics`/`chemistry` | 「你说的非欧几何，在 44 天潮汐应力下还成立吗？」 |

### 6.4 校验项（新增）

| ID | 规则 | 级别 |
|---|---|---|
| **N07** | `consistency.redteam` ≥5 条，每条 `target` 可解析 | warn |
| **N08** | 交付前 `open` 数必须为 0 | error（`--strict`） |

### 6.5 验收

- 赫利孔补 5 条红队，至少 2 条导致设定或代价变化（写进 `history.revisions`）。
- `export` 的世界档案里出现「## 红队报告」一节（表格：质疑 / 打哪 / 结论 / 修补）。
- `selftest` 新增 E10：红队生成 5 条且 target 全部可解析；E11：`--strict` 下有 open 时非零退出。

## 8. 功能 D · 元胞自动机（化生斧的引擎）

> 这一件是作者看了评论区（BV1JUsX6mEHT · 鲲鹏s「可以整点元胞自动机之类的，也是世界」）之后拍的板：**进 1.1，不再往后推。**

### 8.1 要解决什么

1.0 的生态是「填」出来的：`biology.trophic_levels` 里份额是手写数字，`mass_extinctions` 是一次性描述。世界不自洽也看不出来。

CA 把这一层改成「跑」出来：给局部规则 + 初值，稳态密度、周期、塌缩概率是算出来的，`trophic_levels` **必须与 CA 结果一致**，否则机检报错。这一步也顺手治了 1.0 的头号毛病——参数表。

### 8.2 数据模型（新增，可选）

```json
"biology": {
  "evolution": {
    "ca_rule": "forest-fire",
    "grid": [200, 150],
    "steps": 400,
    "seed": 7,
    "params": { "grow": 0.004, "lightning": 0.0006 },
    "summary": {
      "steady_density": 0.319,
      "cycle_steps": 70,
      "collapse_prob": 0.05,
      "measured_at_step": 400
    },
    "figures": ["out/helikon/ca-t0.png", "out/helikon/ca-t200.png", "out/helikon/ca-t400.png"],
    "status": "ok"
  }
}
```

- 只存**参数 + 摘要 + 图路径**，不存每格状态（200×150 存不下，也不该进数据源）。
- `figures` 由 `ca --run` 生成到用户指定目录（默认 `out/<世界id>/`），**不许写进技能目录**。
- `summary` 必须是跑出来的；手填的会被 `--check` 用同 seed 复算打回。
- `params` 的键随规则而定，`custom` 见下。

### 8.3 CLI

```bash
python scripts/pangu.py ca world.json --rule forest-fire --grid 200x150 --steps 400 --seed 7 --out out/helikon
# → 稳态密度 0.319 ｜ 火周期 70 步 ｜ 塌缩概率 0.05 ｜ 图 3 张 → out/helikon/

python scripts/pangu.py ca world.json --check     # 读 evolution，复算一遍比对 summary
python scripts/pangu.py ca world.json --write --yes  # 复算结果写回 world.json
```

内置规则（纯 Python，够用）：

| 规则 | 状态 | 更新 | 报告 |
|---|---|---|---|
| `forest-fire` | 0 树 / 1 空地 / 2 燃烧 | 树且四邻有燃烧 → 起火；燃烧 → 空地；空地以 `grow` 长树；树以 `lightning` 遭雷击 | 稳态树密度、火周期、塌缩概率 |
| `predator-prey` | 0 空 / 1 草 / 2 食草 / 3 食肉 | 按局部计数 + 概率 | 三方密度的周期与振幅 |
| `custom` | 3–5 状态、4 或 8 邻居 | `rules` 表：每行 = 邻居和区间 → 下一状态，逐行解释执行 | 由 `rules` 里的名称决定 |

性能预算：400 步 × 30000 格 ≤ **30 秒**（纯 Python 单核）。超了就说明内层循环写崩了，去优化局部变量/预取邻居，别加依赖。

### 8.4 输出图片：零依赖是硬要求

**PIL 不是标准库，不许 import。** 用 `zlib + struct` 手写最小 PNG 编码器：

- 组成：8 字节签名 + `IHDR`（宽、高、位深 8、颜色类型 2=RGB）+ `IDAT`（每行前置 filter 0，`zlib.compress`）+ `IEND`
- 每段 = 长度(4) + 类型(4) + 数据 + CRC32(4)，CRC 用 `zlib.crc32`
- 单独写成 `scripts/png_writer.py`（约 40 行），供 `ca` 和将来的图表复用
- 自检：文件头必须是 `\x89PNG\r\n\x1a\n`，IHDR 里的宽高与请求一致（selftest 断言）

### 8.5 浏览器端：「演化」视图

`preview_template.html` 加第 4 个视图按钮 `v-life`（排在 `v-sys / v-body / v-far` 之后）：

- 左：2D canvas 实时跑同一条 CA（`evolution.params` + `seed`）
- 右：时空图（时间轴向下刷），就是「痕迹」的可视化
- 顶：`steady_density / cycle_steps` 与 world.json 的 summary 对照，差 >5% 红字提醒
- PRNG：用 `Math.imul` 写一个 32 位 PRNG（xorshift 或 mulberry32），与 Python 端**同规则同参数同 seed** 时统计结果一致（允许逐格不同，密度差 >5% 算 bug）

### 8.6 校验项（新增）

| ID | 规则 | 级别 |
|---|---|---|
| **N09** | `evolution` 存在时 rule 合法、`grid ≤ 512×512`、`steps ≤ 5000`、seed 为整数 | warn |
| **N10** | `trophic_levels[].share` 之和与 `steady_density` 一致（±10%）；不一致报「手填与跑出来的对不上」 | warn |
| **N11** | `sky_phenomena` 提到周期灾变（含「每…天」）时，`cycle_steps > 0` | warn |

### 8.7 验收

1. 赫利孔补 `evolution`（forest-fire / 200×150 / 400 步 / seed 7），跑出稳态 **0.319** 写回；`validate` 仍 100/100。
2. 把 seed 改成 8 再 `--check` → 必须报 summary 不匹配（**证明它是真跑，不是抄的**）。
3. 3 张图进 `examples/helikon/`，世界档案里嵌一张。
4. `ca --run` 同一 seed 跑两次，summary 完全一致（可复现是底线）。
5. `selftest` 新增 E16/E17/E18（见 §9.2）。

### 8.8 与三律的接法（写进 references，别让它变成装饰图）

- **逆行律**：CA 的规则本身就能反常识（比如「火不烧树，只烧空地」）。
- **代价律**：CA 的代价可量化——稳态密度、周期长度、塌缩概率。
- **痕迹律**：时空图就是居民抬头能看见的那场周期灾变。

**硬规则：CA 必须改变至少一个 `trophic_levels` 的数字或 `sky_phenomena` 的一条描述。** 只是摆一张好看的格子图，不算数。
