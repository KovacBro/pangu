# 开发文档 · v1.1.6 编年层

> 范围：`scripts/chronicle.py`（新增）、`pangu.py` 的 `chronicle` 子命令与 `export` 接入、
> `review.py` 的 D12、`selftest.py` 的 V13–V18、MCP 的 `pangu_chronicle`。
> 一句话：**把「人」这一层从散文变成推演**，而且用跟 `entail` / `ca` 同一套规矩。

## 1. 为什么是这一层

1.0–1.1.5 依次立起了六层：律（`physics`）、地（`map`）、改（`patch`/`sweep`/`diff`）、
路标（`plan`/`options`）、天（`sky`/`sky --year`）、账（`kernel`/`ledger`/`certify`/`replay`）。

唯独 `civilization` 与 `history` 只有**作者手写的散文**：

```json
"civilization": {"exists": true, "name": "灰阶诸城", "tech_path": "…", "taboo": "…"}
"history":      {"eras": [{"name": "双源纪", "span": "约 21 亿年前 – 40 万年前"}, …]}
```

它的问题不是「写得不好」，而是**不可证伪**：三个纪元标题可以套在任何世界上。
读者问「那三千年里发生了什么」，引擎没有答案。

1.1.6 的立场：**史可以推**，只要承认它推的是「时刻与顺序」，不是「剧情」。

## 2. 推演链

```
carrying_capacity.humans_subsistence   ─┐
planet_map.summary.mean_temperature_k  ─┼─▶ K, fit ─▶ r, p_peak
planet_map.tidal_locked                ─┘                 │
                                                          ▼
cosmology.calendar.{day_hours, year_days, months, month_days}
                                                          │
civilization.{taboo, energy_source, timekeeping, …}       │
cosmology.{stars, sky_phenomena}                          ▼
                              ┌──────── 人口曲线（logistic）
                              │  P(t) = K / (1 + (K/P₀ − 1)·e^{−rt})
                              ▼
                     事件时刻表（q ∈ [0,1]） ─▶ t = q·t_max ─▶ people = P(t)
                              │
                              ▼
              19 条规则 ─▶ events[] ─▶ hash（sha1 前 8 位）
```

三个关键定义：

| 量 | 定义 | 出处 |
|---|---|---|
| `K` | 可养活人口 | `biology.carrying_capacity.humans_subsistence`；缺省由 `land_npp_gtc_yr × 9 kcal/g × 1% ÷ 2500 kcal/日` 现算 |
| `r` | 人口增长率 | `(0.00055 + 0.00055·u) × fit`，`u` 是 seed 决定的第一个随机数 |
| `p_peak` | 文明实际峰值占 `K` 的比例 | `0.035 + 0.075·u₂`，`fit < 0.6` 时 ×0.7；夹到 `[0.005, 0.35]` |
| `t_max` | 走到峰值所需的年数 | `ln((K/P₀−1)/(1/p_peak−1)) / r`，下限 400 年 |

`fit = max(0.45, 1 − |T − 288| / 60)`，潮汐锁定时再 ×0.7 —— 这是「气候适配」，
它同时压低增长速率与峰值，所以一个冰封世界的人口曲线起得晚、停得低。

**只有两个自由度**（`r` 与 `p_peak`），都由 seed 决定。这就是「可复算」的全部代价：
想换一条史，换 seed；想改一条史的某一段，改世界，不是改史书。

## 3. 事件规则（19 条）

| ID | 事件 | 触发 / 依据 | 强度 |
|---|---|---|---|
| H01 | 第一笔 | `calendar.epoch` / `day_hours` / `year_days` | 必然 |
| H02 | 定历 | `year_days ÷ month_days` 的余数；整除即「不需要闰日」 | 必然 |
| H03 | 立禁 | `civilization.taboo` 非空 | 很可能 |
| H04 | 能源 | `civilization.energy_source` 非空 | 很可能 |
| H05 | 种子入土 | 有承载力且陆地占比 > 0 | 很可能 |
| H06 | 第一批城市 | 人口刻度 + `ocean_fraction`（沿海 / 河谷） | 很可能 |
| H07 | 文字 | `civilization.timekeeping` 非空 | 很可能 |
| H08 | 出海 | `ocean_fraction > 0.4` 或存在卫星 | 很可能 |
| H09 | 成国 | `civilization.social_shape` 非空 | 很可能 |
| H10 | 争地 | 人口 / 曲线终点（马尔萨斯压力） | 很可能 |
| H11 | 大疫 | 人口密度 | 很可能 |
| H12 | 变法 | `civilization.tech_path` 非空 | 很可能 |
| H13 | 国教 | `sky_phenomena[0]` 非空 | 很可能 |
| H14 | 顶点 | `p_peak × K` | 必然 |
| H15 | 余波 | `fit` 与 seed 决定：停滞 / 外扩 / 断裂 / 衰退 | 很可能 |
| H20 | 双日之民 | 恒星 ≥ 2，取其互绕周期 | 必然 |
| H21 | 没有黑夜 | 恒星总光度 ≥ 1 L☉（且 ≥ 2 颗） | 必然 |
| H22 | 两段睡眠 | `|day_hours − 24| / 24 > 0.25` | 必然 |
| H23 | 晨昏线 | `planet_map.tidal_locked` | 必然 |

**事件时刻表 `q`**：0.00 / 0.02 / 0.04 / 0.06 / 0.10 / 0.16 / 0.22 / 0.30 / 0.34 / 0.38 /
0.46 / 0.50 / 0.56 / 0.68 / 0.76 / 0.84 / 0.90 / 1.00 / 1.15（余波）。

> 常见误解：`q` 是**时间**进度，不是人口进度。logistic 曲线前 70% 的时间只涨到峰值的
> 几个百分点——这正是真实人口史的形状（采集 20 万年、农业 1 万年、工业 300 年），
> 所以文案里报的是绝对人口，不报「已完成百分之几」。

**顶点之后进入平台**：`_ev` 把 `people` 夹到 `min(P(t), p_peak·K)`，否则「余波」
会比「顶点」人更多——那是把理论上限当成了历史事实。

## 4. 数据契约

写入 `history.chronicle`（生成物，**不要手填**）：

```json
{
  "generator": "chronicle/1.1.6",
  "seed": 7,
  "hash": "d94a6f21",
  "calendar": {"epoch": "落火元年", "day_hours": 31.4, "year_days": 355.9, "months": 8, "month_days": 44.49},
  "population": {"start": 5000, "carrying_capacity": 62900000000, "carrying_capacity_source": "biology.carrying_capacity.humans_subsistence",
                 "peak": 2910000000, "peak_share": 0.046, "growth_per_year": 0.00073, "model": "logistic：P(t)=K/(1+(K/P0-1)e^(-rt))"},
  "summary": {"n_events": 18, "span_years": 21116, "climate_fit": 1.0, "eras": [{"name": "萌芽纪", "from_year": 0}, …]},
  "events": [{"id": "H01", "kind": "origin", "title": "第一笔", "text": "…",
              "t_year": 0, "era": "萌芽纪", "q": 0.0, "people": 5000,
              "src": ["cosmology.calendar.epoch"], "strength": "必然"}]
}
```

`src` 的取值规则：只保留 `ws.resolve_path(world, p)` 为真的路径；全空则退化为
`["meta.name"]`。**没有出处的史不许存在** —— 跟 `ca` 的 `source`、`entail` 的 `src`
是同一条规矩，理由也一样：答不出「由哪个字段推得」的句子，不该出现在引擎的输出里。

## 5. 判定

### `chronicle --check`（退出码 1 = 不过）

三把尺子：

1. **`self_ok`**：`event_hash(存档 events) == 存档 hash`。手改一句史书、改一岁，
   hash 立刻对不上。这是「手改检测」。
2. **`hash_ok`**：`存档 hash == derive(world, seed=存档seed).hash`。改了下游字段
   （承载力、历法、天象）却没重跑 `--write`，这里会红。这是「漂移检测」。
3. **`stale` / `over`**：事件的 `src` 逐条验证；事件人口不得超过 `K × 1.02`。
   **史不能比地能养的多。**

### `review` D12 编年（软门槛）

| 情况 | 判定 |
|---|---|
| 没有 `history.chronicle` | SKIP（可选层，不拦交付） |
| `--fast` | SKIP（不复算） |
| `--check` 三项全过 | ✓ |
| 任一项不过 | ! （软门槛，不拦交付，但列进「可以更好」） |

为什么是软门槛：文明是可选层（`civilization.exists` 可以是 `false`）。把可选层设成硬门槛，
会让「一个只有地质史的世界」永远交付不了。

## 8. 已知限制

1. **人口模型只有一个台阶**：一阶 logistic，不区分农业/工业/信息跃迁。真实人口史的
   「台阶」来自技术革命，这里用 `p_peak` 一个数把整段压缩掉了。
2. **战争只有一条**：由人口压力推出「会发生」，不推交战双方、战线与结果。
   多文明交互（`civ-atlas` 那一类的事件堆）没有建模。
3. **不写人名与国名**：名字是作者的活，年份与因果是引擎的活。
4. **`q` 是设计参数**，不是从物理里解出来的。它的作用是让事件在时间轴上分布得可读；
   真正的因果在「事件凭什么发生」那一列，不在 `q` 上。
5. **`civilization.exists=false` 时仍然会出史**（只剩自然史与天象条目）。
   要不要 `--write` 由作者决定，引擎不替它删。
6. **没有与 `history.eras` 做机检对齐**：作者的纪元用 `span` 字符串写，引擎不解析它，
   所以两套时间轴可能不一致——这是刻意的（上位叙事归作者），但要知道。

## 9. 主产物：地图从预览页开出去

### 走过一段弯路

第一版把 `mapgen` 的 8 个场（180×90）base64 内联进 `preview.html`，页面自己着色。
单文件是成立了，但 180×90 放大到 1000px 宽就是一片模糊——原生 `map.html` 是 1440×720 的 PNG，
差出两个数量级。所以这一版退回去：**预览页只负责开一扇门**。

### 现在的做法

- `preview` 时检查**输出文件同目录**有没有 `map.html`，有就注入 `map.html`，没有就注入空串。
- 模板里 `<script id="pangu-map-href" type="text/plain">` 存这个地址；dock 的「地图」按钮
  `window.open(href, '_blank')`。
- 地址为空时按钮 `display:none`，不给点了没反应的入口。
- `--no-map` 强制不挂入口；`--fast` 与它无关（不再需要算地图）。

体积：预览页回到 246 KB（内嵌那版是 433 KB）。

### 优化成果给了原生那一版

内嵌版里做对的东西没有白做，全部移植到 `map.html`：

| 成果 | 落点 |
|---|---|
| **每层图例** | `_viewer_payload` 新增 `legend`；色带由 `RAMP_*` 直接生成 CSS 渐变 |
| **标尺与图同源** | 抽出 `_render_ranges(res)`，`_render_layer` 与 payload 都从这里取数 |
| **按本星归一** | 本来就有（`max_elev`、温度取 2%–98% 分位），这次把口径写进图例文字 |
| **冰盖压白** | 本来就有（`temp < 271` 叠白），图例里点明 |

`legend` 的结构：

```json
{
  "elevation": {"grad": "linear-gradient(90deg,rgb(74,86,62) 0%,…)", "lo": "0 km", "hi": "5.6 km", "note": "…"},
  "tectonics": {"items": [["#e85c48","聚合边界"], ["#48c8d2","张裂边界"]], "note": "…"}
}
```

前端 `renderLegend()` 在 `setup()` 与每次切层时调用；群系层走色块分支，板块层走 `items` 分支，
其余层走渐变分支。

### 两条设计约束

1. **图例不许手写**。色带与标尺都从渲染参数生成，否则「图上那片红」和「图例说 300 K」各说各话。
2. **地图是加法不是依赖**。入口找不到、`map.html` 不存在、推演抛异常，都只影响这一个按钮，3D 照常。

## 9.5 切片接上时间轴（收尾的一根线）

§8 第 3 条说「不写人名与国名」，但写切片的人（作者或模型）仍然要凭空想「这个人活在哪一年」。
1.1.6 把这条线补上：`slice --prompt` 直接读存档的 `history.chronicle.events`，取这个人之前的 3 件事。

```
--at-year 5000  →  第 1,836 年 能源〔很可能〕农耕纪 · 全境 2 万 人
                   第 2,938 年 种子入土〔很可能〕农耕纪 · 全境 4 万 人
                   第 4,040 年 两段睡眠〔必然〕农耕纪 · 全境 9 万 人
                   他活在第 5,000 年：之后的事，他一无所知
```

三条约束：

1. **只读存档，不现场 `derive`**。史是 `--write` 定过稿的那一份，切片引用的就是它；否则「切片引的史」与「档案里的史」会各说各话。
2. **取不到就说取不到**：没有 `history.chronicle` → 「这个切片还没有前情」；`--at-year` 早于第 0 年 → 「这个人活在成文史之前」。两条都不编。
3. **硬要求多一句**：前情只准用列出来的编年（D12 会对账）；人名、地名、国名仍归作者。

验收：V22（年份都来自存档编年）、V23（`--at-year` 截断 + 成文史之前）。

## 10. 为什么不做成「事件堆 + 多文明」

`civ-atlas` 那一类工具的做法是事件堆驱动：每个势力有性格、有目标，互相触发。
那能长出好故事，但它的输出**不可复算也不可证伪**——同一份存档，换一版权重就是另一段史。

盘古选了另一条：**从量推出事件，而不是从事件推出量**。
代价是史很「骨架」（18 条），收益是每一句都能回答「你凭什么这么说」。
等 `civilization` 有了势力、人口、资源的结构化字段，再谈事件堆不迟——
那时候事件堆也不会是随机的，仍然要从承载力里长出来。


## 11. 命名层（`naming`）

§8 第 3 条把「人名与国名」划给了作者。这话成立，但作者真正需要引擎做的是**骨**：读音怎么排、地名后缀什么意思。1.1.6 补这一层，边界划在这里 —— 引擎给骨架，字归作者。

```
meta.id 的字母  ──▶ 音系（辅音 / 元音 / 韵尾）
land_fraction   ──▶ 地形（coast / inland / none）──▶ 后缀语义（岸/渡/滩 或 地/垒/野）
seed + 音系 + 构词规则 ──▶ 人名（名 + 氏族）/ 地名（词根 + 后缀）──▶ hash
```

四条约束：

1. **音系有出处**：从 `meta.id` 抽字母；不足 `MIN_CONSONANTS = 8` / `MIN_VOWELS = 4` 时用默认集补位，补的东西记在 `phonology.borrowed`，`origin` 记 `meta.id` / `meta.id+default`。音系一旦写进 `civilization.names.phonology`，此后优先用它（`origin = author`）。
2. **地形只读不猜**：`biology.carrying_capacity.land_fraction` → `cosmology.bodies[0].planet_map.summary.land_fraction` → `ocean_fraction` 反推；三级都缺就 `terrain = none`，后缀退化为通用池。
3. **双 hash 对账**：`--check` 算两次 —— `now`（拿现在的世界重推）与 `live`（拿存档里那几个名字算）。前者红了说明音系 / seed 变了；后者红了说明名字被手改。
4. **可拆可溯**：每个名字带 `syllables` / `rule` / `src`；`src` 里只放真能被 `resolve_path` 解析的字段。开发中曾塞过 `naming.DEFAULT_*` 这种假路径，`--check` 当场判失效 —— 正确的修法是别生成假路径，而不是给体检放行。

已知边界：不做语法与句法、不做语义漂移；不翻中文（哪个 Tal 写成「塔尔」仍归作者）；单音节词允许（`Lek` / `Kol`），短名在语料里是常态而不是缺陷。

验收：V24（结构 + 可拆可溯）、V25（同 seed 同 hash）、V26（写回绿 / 手改红）、V27（`--set-phonology` 接管）。
