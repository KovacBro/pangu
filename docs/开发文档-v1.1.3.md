# 盘古 1.1.3 · 导航与选项（开发文档）

> 1.1.1 让世界有了**地**，1.1.2 让**改动**可验证，1.1.3 让**流程**可导航、让**想象力**可供给。
> 本文记录 1.1.3 的范围、数据契约、算法、判定标准与验收。面向维护者；第一次用盘古的人读 `SKILL.md`。

---

## 1. 定位：两个真问题

1.1.2 之后，引擎的能力已经够造世界，但用起来仍然卡在两处：

| # | 症状 | 根因 | 1.1.3 的解法 |
|---|---|---|---|
| 1 | agent 每轮都要重读 `SKILL.md` 才知道自己在第几步；跑完 `validate` 只知道「有 3 个 fatal」，不知道「下一步该干什么」 | 七斧只是**文档里的表**，没有进入引擎 | **大条 A · 七斧状态机** `plan` |
| 2 | 设定容易落进「双星 + 超级地球」的安全套路；改得越猛越像噪声，改得越稳越像换皮 | 缺一层「**命题 → 互斥选项 → 代价**」的菜单，只有横向的积木库 | **大条 B · 选项卡** `options` |
| 3 | 现象（`sky_phenomena`）靠想，想到的就写，想不到的整层空着 | 没有「从已立之律推出可见现象」的机制 | **大条 C · 必然推论** `entail` |

三者的关系是一句话：**`plan` 告诉你现在该回答哪一问，`options` 给这一问几种活法，`entail` 把你选完的结果推成居民看得见的东西。**

同版第二批补上闭环的两端（§11、§12）：**`review` 判断「能不能交」**（八项体检、一个结论，只读可反复跑），**`whatif` 回答「如果当初选另一条会怎样」**（内存副本上改设定，推演后果，永不写原世界）。五个命令合起来才是一次完整的 1.1.3。

```
plan ──▶ options ──▶ patch ──▶ validate --brief ──▶ entail ──▶ slice / map / ca / redteam ──▶ export
 ↑                                                                                              │
 └──────────────────────────────  每轮都回到 plan  ─────────────────────────────────────────────┘
```

### 不做

- 不做自动写设定：`options` 只给菜单，采纳要人点头（`--adopt`），正文仍由作者/agent 写。
- 不做 schema 迁移：所有新数据都是**可选**字段，1.1.2 及更早的 `world.json` 原样可读、分数不变。
- 不做因果倒推：`entail` 只从设定推现象，绝不从现象反推设定。
- 不做流程强制：`plan` 只报告，不拦截；`validate --strict` 仍是唯一硬门槛。

## 2. 设计约束（不能破的）

| 约束 | 含义 | 为什么 |
|---|---|---|
| **新增即可选** | `seed.brief`、`cosmology.energy_source`、`〔entail Exx〕` 标记全部可缺省 | 旧世界不该因为换版本掉分或报错 |
| **单一数据源** | `plan` 不写盘；`options --adopt` 与 `entail --write` 走 `world_tuning` 的版本推进与修订记录 | 与 1.1.2 的调参层同一套账 |
| **判定写死** | 斧位的收斧条件写死在 `rite._missing()`，不放给模型判断 | 同一份 world.json 每次必须判出同一斧 |
| **文档与代码同源** | 斧名、斧序、每斧的提问与检索写在 `rite.AXES`，与 `SKILL.md` 的七斧表一一对应 | 两边漂移比没有状态机更糟 |
| **不给免费奇观** | 每个选项必须写代价；没写代价的卡会被 `R01` 点名 | 代价律是灵魂，不能输在菜单上 |
| **幂等** | 采纳同一 `qid` 覆盖旧选择；推论按 `〔entail Exx〕` 去重 | 反复运行不该长出一堆重复 |

## 3. 大条 A · 七斧状态机（`scripts/rite.py` + `plan`）

### 3.1 斧位怎么判

```python
plan_report(world) -> {axe, states[7], missing[], asks[], searches[], commands[], gates[6]}
```

- 逐斧跑 `_missing(world, n)`，返回**缺口字符串列表**（空 = 收斧）。
- 第一支未收斧标 `current`，之前标 `done`，之后标 `todo`；斧 6 可选，未开时标 `skipped`，**不抢斧位**。
- 七斧全收时斧位停在 7，交给 6 项交付门槛。

| 斧 | 收斧条件（可机检） |
|---|---|
| 1 混沌 | `meta.name`、`seed.core_paradox`、`seed.resolution` 非空；`meta.aesthetic` ≥2 |
| 2 分判 | `has_stars` 已声明（无恒星须给 `energy_source`）、`bodies[0]` 有半径/质量/`orbit.a_au`、`calendar` 有日长与年长、`sky_phenomena` 非空 |
| 3 立律 | `physics.constants` ≥1 且**至少一条真的改了值**、每条改动有 `why`、有 `laws` 或 `new_interactions`；`mathematics` 建议非空 |
| 4 炼质 | `chemistry.periodic_status` / `solvent` / `key_bonds` / `signature_materials` 齐 |
| 5 化生 | `energy_currency.name` / `genetic_carrier.name` / `trophic_levels` ≥2 且份额≈1；`biochemistry` 建议非空 |
| 6 启智 | `civilization` 非空（`exists:false` 视为已过）；否则 `timekeeping` / `tech_path` / `taboo` 齐 |
| 7 演界 | `validate` fatal = 0；`history.eras` ≥1；`narrative` 三件套齐 |

### 3.2 交付门槛（G1–G6）

斧位讲「写到哪」，门槛讲「能不能交」：

| ID | 门槛 | 判定 | 建议命令 |
|---|---|---|---|
| G1 | 自洽 | `fatal == 0` | `validate --strict` |
| G2 | 反常识度在推荐带 | `40 ≤ weirdness ≤ 70` | `validate` |
| G3 | 第一人称切片已定稿 | `narrative.slice.status == "ok"` | `slice --strict` |
| G4 | 红队全部结案 | 无 `verdict: open` | `redteam --check` |
| G5 | 行星地图可复算 | `planet_map.hash` 存在 | `map --check` |
| G6 | 创作简报无冲突 | 卡间无互斥、卡与数据对得上 | `options --check` |

### 3.3 输出

```
【盘古 · 七斧进度】赫利孔 v1.1.3 ｜ 100/100 ｜ fatal 0
  ✓1 混沌  ✓2 分判  ✓3 立律  ✓4 炼质  ✓5 化生  ✓6 启智  ▶7 演界
  当前：斧7 演界（定史）  →  写 history、consistency、narrative
【还缺】…
【这一斧要回答】1. … 2. …
【检索（锚定 / 证伪 / 取反）】…
【交付门槛】6/6 已过
【下一步】1. entail <world>  └ …
```

三种投影：`plan`（人读，含提问与检索）、`plan --json`（机读）、`plan --brief` / `plan --next`（一行 / 一条命令，供 agent 循环）。

## 4. 大条 B · 选项卡（`references/选项卡.md` + `scripts/options_lib.py` + `options`）

### 4.1 分层

| 层 | 文件 | 形态 | 用途 |
|---|---|---|---|
| 积木（1.0 起） | `references/公理库.md` | 62 条，横向按学科/代价 | 「有什么反常识可以捡」 |
| 菜单（1.1.3） | `references/选项卡.md` | 31 个命题 / 132 个选项，纵向按斧 | 「这一斧必须回答哪些问题、各有几种活法」 |

### 4.2 文件文法

```markdown
## 斧 3 · 立律（定法）
### Q3.1 引力还是吸引吗？
@why 这是最贵的一改：它同时改写天体、地形、生物形态与建筑力学。
- A ｜ 设定：… ｜ 代价：… ｜ 痕迹：… ｜ 连锁：physics.constants ｜ 标签：正引力 基准
- B ｜ 设定：… ｜ 代价：… ｜ 痕迹：… ｜ 连锁：physics.new_interactions ｜ 标签：-正引力 斥力
```

- `###` 命题号 `Q<斧>.<序>`；`@why` 一句说明这一问为什么重要。
- 选项五个字段固定：`设定 / 代价 / 痕迹 / 连锁 / 标签`；缺「设定」或出现未知字段进 warnings，不中断解析。
- `连锁` 是**要顺手写的字段路径**（`physics.constants`、`biology.biochemistry` …），把「选项」直连到「schema」。
- `标签` 里 **`-` 前缀表示排除**：`-有恒星` 与别的选项的 `有恒星` 同时出现即判互斥。

解析失败不抛异常：`parse_cards` 返回 `(cards, warnings)`，坏行进 warnings，其余照常可用。

### 4.3 采纳（`--adopt`）

```bash
options world.json --adopt "Q3.1=B"
```

1. `find_option` 解析 `Q3.1=B`（也接受 `Q3.1B` / `q3.1 = b`）。
2. `make_choice` 把卡压成一条记录，**保留代价与痕迹**（不能只剩一个字母）：

```json
{"qid": "Q3.1", "axe": 3, "title": "引力还是吸引吗？", "option": "B",
 "label": "引力改号，同质量相斥", "cost": "物质无法靠引力聚集成团……",
 "trace": "抛出的石头加速飘向天顶……", "tags": ["-正引力", "斥力"],
 "fields": ["physics.new_interactions", "broken_symmetries", "cosmology.topology"],
 "date": "2026-11-02"}
```

3. 同一 `qid` 后写覆盖先写（`merge_choices`），按 `Qn.m` 排序。
4. `card_conflicts` 查卡间互斥，`card_world_mismatch` 查卡与数据的一致性（见 §5）；有互斥则拒绝，`--force` 才放行。
5. 写盘走 `world_tuning.record_revision`：版本补丁位 +1、`history.revisions[]` 追加、`fields` 记 `seed.brief.choices`。

### 4.4 卡与世界的对账

选项卡只是**决策记录**，不改世界数据。所以「我选了无恒星」与「我写了三颗恒星」可以同时存在——这是必须报出来的不一致：

| 标签 | 机检的事实 | 判定 |
|---|---|---|
| `有恒星` / `-有恒星` | `cosmology.stars` 非空 | 不符即 warn |
| `锁定` / `-锁定` | `rotation_hours is null` 或 `planet_map.tidal_locked` | 同上 |
| `光合` / `-光合` | `biology.photosynthesis` 是对象 | 同上 |
| `水溶剂` / `-水溶剂` | `chemistry.solvent.name == 水` | 同上 |
| `碳基` / `-碳基` | `biology.biochemistry.base` 含「碳」 | 同上 |

未登记事实的标签只当创作备注，不检查——避免把自由表达判成错误。

## 5. 大条 C · 必然推论（`scripts/entailment.py` + `entail`）

### 5.1 规则形态

```python
{"id": "E01", "name": "双影", "claim": "…", "why": "…", "trace": "…",
 "src": ["cosmology.stars[0].temp_k"], "strength": "必然",
 "phenomenon": "「双影」…〔entail E01〕"}
```

- 每条规则是一个纯函数 `world -> dict | None`，条件不满足返回 `None`。
- `strength` 两档：`必然`（可由数值直接算出）/ `很可能`（生态与社会的合理外推）。**没有「也许」**。
- 单条规则抛异常只丢这一条，不影响整批（`derive` 里 try/except）。

### 5.2 规则表（30 条）

| ID | 触发条件 | 推论 |
|---|---|---|
| E01 | ≥2 颗恒星 | 双影（两星色温差 → 影子边缘颜色不同） |
| E02 | ≥3 颗恒星 | 不落的灯，没有真正的黑夜 |
| E03 | 无恒星 | 恒黑之天，方位感来自地热而非太阳 |
| E04 | 潮汐锁定 | 固定的晨昏线，影子无限拉长 |
| E05 | 自转 < 14 h | 碎云，一天四次晴雨 |
| E06 | 自转 > 40 h | 昼与夜是两个气候 |
| E07 | 倾角 > 40° | 半年的太阳（极昼进中纬度） |
| E08 | 倾角 < 5° | 没有四季，历法里没有春秋 |
| E09 | 表面重力 > 1.5 g | 没有翅膀，只有滑翔与弹跳 |
| E10 | 表面重力 < 0.6 g | 巨型生物 + 大气在变薄 |
| E11 | 气压 > 200 kPa | 听得见的远方，没有悄悄话 |
| E12 | 气压 < 40 kPa | 会沸腾的湖 |
| E13 | 温室 > 60 K | 没有冰的颜色 |
| E14 | 反照率 < 0.15 | 吸光的土地，昼夜温差被放大 |
| E15 | 年长 > 500 d | 长得记不住的一年 |
| E16 | 年长 < 100 d | 密到数不清的纪年 |
| E17 | 日长偏离 24 h > 30% | 睡两觉的一天 |
| E18 | 有卫星 | 可走的潮间带 |
| E19 | 无卫星 | 不动的海 |
| E20 | 海洋 > 90% | 没有远方，只有群岛 |
| E21 | 海洋 < 15% | 盐与沙，水权最硬 |
| E22 | 最高峰 > 12 km | 走到呼吸不到的地方 |
| E23 | 溶剂非水 | 不是水的雨 |
| E24 | 有虚构元素 | 会发光的矿 |
| E25 | 守恒破缺 | 算不平的账 |
| E26 | 光速 ≤ 1% c | 看见的都是旧事 |
| E27 | 能量源含「潮汐」 | 会呼吸的地面 |
| E28 | 双星色温差 > 1500 K 且有光合 | 两面的叶子 |
| E29 | 每年昼夜数 < 30 或 > 800 | 几十个昼夜 / 数不清的昼夜 |
| E30 | 行星周期 / 双星周期 ≈ 整数 | 不用闰的年 |

E30 是最好的一条示例：赫利孔 355.9 d ÷ 44.49 d = 8.00，于是「一年正好 8 个双星周期、历法不需要闰日」不是设定者的巧思，而是开普勒第三定律的**结算**。

### 5.3 回写与失效

```bash
entail world.json                 # 只看
entail world.json --write --yes   # 追加到 cosmology.sky_phenomena
entail world.json --check         # 体检：有没有因改设定而失效的旧推论
```

- 回写格式：`「现象名」<痕迹>〔entail E01〕`，前缀用「」是因为 `slice` 的 N05 用「」抽现象名，一次满足两处。
- 去重按 `〔entail Exx〕`：同号只留第一条，重复的删掉；已在册的跳过。
- **失效检测**：标记存在但当前规则不再触发 → `--check` 退出码 1 并点名。这是「改了设定忘删旧天象」的唯一自动化防线。

## 7. 数据契约

### 7.1 `seed.brief`（可选，1.1.3）

```jsonc
{
  "seed": {
    "brief": {
      "updated": "2026-11-02",
      "choices": [
        {"qid": "Q2.1", "axe": 2, "title": "天上有什么？", "option": "B",
         "label": "内层双星互绕，行星绕两者公转",
         "cost": "行星轨道必须 ≥2.5 倍双星间距……",
         "trace": "两道颜色不同的影子……",
         "tags": ["有恒星", "双星"],
         "fields": ["cosmology.stars[0..1].orbit", "bodies[0].orbit.a_au"],
         "date": "2026-11-02"}
      ]
    }
  }
}
```

- `choices` 缺失 → `R01` 记 skip，不扣分。
- 同一 `qid` 只保留一条；顺序按 `Qn.m`。

### 7.2 `cosmology.energy_source`（可选，建议无恒星世界必填）

字符串，例如 `"潮汐摩擦 + 放射性衰变（地幔富集 ⁴⁰K）"`。斧 2 的收斧条件在 `has_stars=false` 时会检查它；`entail` 的 E03/E27 会读它。

### 7.3 `cosmology.sky_phenomena[]` 的推论标记

以 `〔entail Exx〕` 结尾的条目视为**引擎生成**；`entail --write` 按编号去重，`--check` 按编号验活。手写条目不需要标记。

### 7.4 `validate` 新增检查

| ID | 维度 | 规则 | 级别 |
|---|---|---|---|
| R01 | 叙事 | 已采纳的卡之间无互斥；卡与世界数据对得上；每张卡都写了代价 | warn（无卡时 skip） |

评分公式不变：`100 − 25×fatal − 4×warn − 2×missing`。

## 9. 已知限制

- `plan` 的收斧条件是**必要不充分**：字段齐了不代表写得好。它只回答「能不能往下走」，不回答「写得对不对」。
- 选项卡的 132 个选项是**人工写的菜单**，只能覆盖常见活法；冷门方向仍要靠公理库与检索。
- 互斥只支持「一正一负标签」这一种形态，表达不了「A 与 B 二者只能有其一但都不是极值」这类复杂约束。
- `entail` 的 30 条规则是阈值型，不理解「为什么」；推论成立不等于设定优雅。
- `entail --check` 只能发现「规则不再触发」，发现不了「规则仍触发但描述已过时」（例如改了恒星名）。
- `options --adopt` 不自动改数据：卡说「无恒星」不会删掉 `cosmology.stars`。这是故意的——**采纳是决策，改数据是另一件事**，中间的落差由 `R01` 提醒。
- `plan` 每轮都跑一次 `validate`（含 CA 编译），大世界约几十毫秒，可接受但不为零成本。
- `review` 不判断「写得好不好」：D3 只数字数与机检项，像说明书的切片它也会放行——文风与想象力没人能机检。
- `review` 把「没做」和「做错」分开：没有地图哈希、没跑过演化记 skip，不算失败；但一旦有哈希就必须复算一致。
- `whatif` 只改数据、不重推地图与生态：`--recalc` 只能抹平密度/重力这类算术冲突，地形与群系得真跑 `map` / `ca`。
- `whatif` 的推论增减只反映「触发条件变了」，不保证描述仍准确：E09 可能还在触发，但句子里的重力数字已过时。
- `PANGU_ASCII` 只换字形：中文照旧，所以真正的 GBK 控制台仍需要 `chcp 65001`；它解决的是「符号显示成问号」这一类问题。

## 11. 大条 D · 交付体检（`scripts/review.py` + `review`）

### 11.1 动机

1.1.3 第一批把「怎么造」讲清楚了（`plan` / `options` / `entail`），但**交付前要跑六条命令**：`validate --strict`、`slice --strict`、`redteam --check`、`map --check`、`ca --check`、`entail --check`。漏一条就是漏一条，而且没有人替你把这些结论汇成一个「能交 / 不能交」。

`review` 就是那个汇合点：**一条命令、八项结论、一个判断**。

### 11.2 八项

| ID | 项 | 判据 | 级别 | 命令 |
|---|---|---|---|---|
| D1 | 自洽 | `fatal == 0` | hard | `validate --strict` |
| D2 | 反常识度 | 40 ≤ weirdness ≤ 70 | soft | `validate` |
| D3 | 切片 | 180–260 字 + `status=ok` + N04/N05/N06 无 warn | hard | `slice --strict` |
| D4 | 红队 | ≥5 条、无 `open`、靶点全部可解析 | hard | `redteam --check` |
| D5 | 地图 | 有 `hash` 且同 seed 复算一致、六项体检通过 | hard（无 hash 时 skip） | `map --check` |
| D6 | 演化 | 有 `summary` 且复算逐项对齐；无 `biology.evolution` 时 skip | hard（无 summary 时 skip） | `ca --check` |
| D7 | 推论 | 无失效的 `〔entail〕` 条目；未回写时记 soft | hard（有回写时）/ soft | `entail --check` |
| D8 | 选项卡 | 卡间无互斥、卡与数据对得上；未采纳时 soft | hard（有互斥时）/ soft | `options --check` |

### 11.3 三条判定原则

1. **只读**。不写 world.json、不出图、不回写。体检命令一旦有副作用，人就不敢在交付前反复跑。
2. **「没做」≠「做错」**。没跑过地图记 `skip`（附「先跑 map --run --write」），跑过但复算不一致记硬失败。混淆这两者，等于逼人跳过体检。
3. **单项失败不中断**。任何一项抛异常，记 `skip` 并写原因（`复算失败：KeyError`），其余七项照跑。

### 11.4 输出

```
【盘古 · 交付体检】赫利孔 1.1.3 ｜ 100/100 ｜ fatal 0
----------------------------------------------------------
  ✓ D1 自洽  100/100 ｜ fatal 0 ｜ warn 0
  ✓ D2 反常识度  66/100（推荐 40–70）推荐区间
  ✓ D3 切片  224 字 ｜ status=ok
  ✓ D4 红队  5 条 ｜ 未结 0 ｜ 靶点失效 0
  ✓ D5 地图  hash d544bcfd ｜ 体检 6 项
  ✓ D6 演化  复算一致
  ✓ D7 推论  已回写 7 条 ｜ 失效 0 条
  ✓ D8 选项卡  7 张卡 ｜ 未答 24/31
----------------------------------------------------------
  结论：可交付
```

未过时，先给「先修这些，按顺序」：每条附一句**为什么**和一条可直接跑的命令，最后才给「可以更好」的软项。

### 11.5 与 `plan` 的六项门槛是什么关系

| | `plan` 的 G1–G6 | `review` 的 D1–D8 |
|---|---|---|
| 回答 | **写到哪了**，能不能往下走 | **能不能交** |
| 口径 | 字段完备度为主 | 引擎复算为主（地图、演化都真跑） |
| 后果 | 提示 | 硬失败即「不可交付」 |

重叠的六项含义一致；`review` 多出 D6 演化与 D7 推论——这两项在 `plan` 里是「斧 5 / 斧 7 的字段」，只有到交付时才有意义。

### 11.6 参数

- `--fast`：跳过 D5/D6 的复算（只看哈希与 summary 是否存在），秒级返回，适合每轮循环末尾。
- `--json`：`{items[8], hard_fail[], soft_warn[], skipped[], ok, conclusion}`。
- `--strict`：硬失败时退出码 1。给 CI 与 `plan --loop` 用。

## 12. 大条 E · 反事实推演（`scripts/whatif.py` + `whatif`）

### 12.1 动机

设定是选出来的，但**选之前没人知道另一条会怎样**。`sweep` 只能扫一个数、只看崩不崩；`diff` 只能比两个已经写好的世界。而作者真正会问的是：

> 「如果把重力再调低 30%，这个世界的生态还成立吗？居民会先失去什么？」

### 12.2 与 `sweep` 的分工

| | `sweep` | `whatif` |
|---|---|---|
| 输入 | 一个数值参数 | 任意多字段（`--set`）或倍率（`--scale`） |
| 输出 | 连续谱 + 第一个崩点 | 代价 / 审查 / 现象 / 下游 四层叙述 |
| 回答 | 「哪一步崩了」 | 「**世界变成什么样**」 |
| 写盘 | 不写 | 默认不写，`--write` 另存 |

### 12.3 算法（五步）

```
1. 校验原世界 → 记下 score / fatal / 现象集合 / 派生量
2. deepcopy → 依次应用 --set（字面值）与 --scale（倍率）
   · --scale 对「数字 + 单位」的字符串保留后缀（见 12.4）
3. 可选 --recalc：按新质量/半径/G 重算 density_gcc、gravity_g、radius_km
4. 重跑 validate + entail：比对 score/fatal、现象的 新增/消失/仍成立
5. 判定改动落在哪一层（地基 / 生态 / 人事 / 表层），给出下游重跑清单
```

### 12.4 单位后缀是这个功能的关键

`world.json` 的常数常写成 `"4.004e-11 m3kg-1s-2"`。倍率缩放如果按 `float()` 处理，会直接报错；如果只取数字、丢掉后缀，下游解析就废了。所以：

```
4.004e-11 m3kg-1s-2  ×0.7  →  2.8028e-11 m3kg-1s-2
```

`_split_num` 把字符串拆成「数 + 后缀」，缩放后 `%g` 回写，后缀原样保留。纯数字（`mass_earth: 26.4`）则保持数值类型，整数结果不退化。

### 12.5 输出

**代价**一行（重力 / 平衡温度 / 反常识度），**审查**一行（评分、fatal、warn）+ 先崩的那条，**现象**分三段（少了 / 多了 / 仍成立），最后一句**分级判断**与下游清单。

```text
  地表重力 1.76 g → 1.23 g ｜ 平衡温度 255.1 → 255.1 K ｜ 反常识度 66 → 66
  审查 100 → 100 ｜ fatal 0 → 0 ｜ warn 0 → 0

【世界少了 1 层】
    - E09 没有翅膀：表面重力 1.76 g：任何靠拍翼起飞的生物都太大、太重……
【仍然成立】6 条：E01、E02、E17、E18、E24、E30
  这是一次「地基」级改动：动了律与天，preview / export / map / ca 全部要重跑。
```

分级措辞不是修辞，是**下游义务的提示**：地基级改动一律要求重跑四件产物，人事级只改档案。

### 12.6 `--write` 的语义

`--write out/假设.json` 写的是**假设世界**，不是「新版本」：不动 `meta.version` 的语义，只在 `history.revisions[]` 追一条 `whatif 假设世界：…`，说明它从哪来。目标已存在时必须 `--yes`。

### 12.7 局限

- 不重推地图与生态：`--recalc` 只抹平密度/重力这类算术冲突，地形、群系、生态相要真跑 `map` / `ca` 才知道。
- 推论增减只看触发条件，不代表描述仍准确（见 §9）。
- 多字段同时改时，因果归属交给读者：`--set A --set B` 的结果不区分是谁造成的。
