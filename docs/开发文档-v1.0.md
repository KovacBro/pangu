## 1. 项目概述

### 1.1 要解决的问题

现有的世界观生成方法有三个结构性缺陷：

1. **倒因为果**：先想要"龙"，再补物理。结果是设定之间互相打架，无法深挖
2. **地球换皮**：改颜色、改名字，法则不变。所谓"异世界"其实是地球的化妆舞会
3. **无代价奇观**：越是夸张的设定，越缺少解释。读者一问就崩

盘古的解法是把顺序倒过来：**先立律，后长物**。世界不是被"设计"出来的，是被"推导"出来的。

### 1.2 核心主张

> 地球不是模板，是一个样本。

物理常数、守恒律、空间维度、元素表、生命溶剂——这些在地球上是"给定"的，在盘古里是"变量"。改一个变量，整个世界跟着变，且变得**可计算**。

### 1.3 能力边界

**能做**
- 从一句话种子出发，产出完整的宇宙-物质-生命-文明四级设定
- 突破行星系统桎梏：壳世界、环世界、无恒星世界、黑洞邻居、非欧空间
- 网页检索校准：用真实科学约束检验虚构，再给虚构定价
- 自洽性机检 + 人检双通道评分
- 结构化 `world.json` → 世界档案 + 可交互 3D 预览

**不做**
- 不做纯文字设定集（那是世界观构建技能的领域）
- 不做角色、剧情、对白
- 不追求设定数量，追求设定之间的**因果密度**

## 2. 设计哲学

### 2.1 三律

| 律 | 内容 | 违反后果 |
|---|---|---|
| 逆行律 | 至少一个底层维度与地球直觉相反 | 世界沦为换皮 |
| 代价律 | 每条反常识都要付出可量化代价 | 世界沦为意淫 |
| 痕迹律 | 代价必须在可观测层留下痕迹 | 世界沦为设定集 |

三律是可机检的：`seed.core_paradox` 非空 → 逆行；`physics.new_interactions[].cost` 非空 → 代价；`cosmology.sky_phenomena` 非空 → 痕迹。`validate` 会检查这三处。

### 2.2 推导链不可逆

```
物理常数 → 宇宙结构 → 天体运动 → 气候 → 化学 → 生态 → 文明 → 历史
```

箭头的方向是硬约束。一旦出现"因为这个文明需要，所以物理是这样"，即为**倒因为果**，审查判 `fatal`。

实现上，这是通过**七斧顺序 + 字段依赖**保证的：`validate` 会检查 `physics` 为空而 `biology` 非空的情况，报 `X02` 致命。

### 2.3 尺度自由

盘古不限定"一个星球"。世界的最小单位由用户定：

| 尺度 | 例子 | 支持度 |
|---|---|---|
| 宇宙尺度 | 多恒星系统、非欧时空、多时间维 | ✅ |
| 行星尺度 | 超级地球、潮汐锁定、气巨浮空 | ✅ |
| 区域尺度 | 一个峡谷文明、一座浮岛 | ✅（中观） |
| 微观尺度 | 一个细胞内部的生态 | ✅（中观） |

`cosmology.frame` 是自由文本，不预设枚举——**任何拓扑都能塞进去**。

### 3.1 分层职责

| 层 | 职责 | 不该做的事 |
|---|---|---|
| L1 运行时 | 对话节奏、提问、推导、决策 | 不算数（交给 L4） |
| L2 检索 | 找参照、找反例、找意象 | 不写设定（只登记 `references`） |
| L3 数据 | 单一事实来源 | 不做校验 |
| L4 计算 | 一切数值判断 | 不改数据（只读） |
| L5 CLI | 编排、IO、格式化 | 不含领域逻辑 |
| L6 呈现 | 视觉表达 | 不发明数据（只消费） |

**关键约束**：L1 的推理结论必须落进 L3 才能被 L4 检查。**只在对话里说、不写进 JSON 的设定，视为不存在。**

## 4. 模块设计

### 4.1 运行时层：七斧状态机

```python
STATES = ["chaos", "dichotomy", "nomos", "materia", "genesis", "anima", "cosmogony"]

# 每个状态的三段式
class Axe:
    ask: list[str]       # 提问脚本（2–3 条）
    search: list[Query]  # 检索配方（1–2 条）
    write: list[Field]   # 写入字段
    check: list[Rule]    # 过关判据
```

**状态迁移规则**
- 顺序推进，不可跳步（`audit` 模式除外，直接进 `cosmogony`）
- 每个状态结束时必须有一次用户可见的"确认点"
- 用户否决时回退到该斧开头，保留已有字段作为候选

**三种模式的差异**

| 模式 | 提问密度 | 检索次数 | 轮次 |
|---|---|---|---|
| `auto` | 低（只汇报） | 4–6 | 1–2 |
| `co-create` | 高（每斧 2–3 问） | 6–10 | 5–8 |
| `audit` | 中（只问冲突点） | 2–4 | 1–2 |

### 4.2 检索层

四类检索（锚定/证伪/取反/质感）各至少一次，总计 ≥4 次，上限 8 次。

**为什么设上限**：检索是手段不是目的。超过 8 次还没写设定，说明在逃避推导。

结果登记为 `seed.references[]`，四字段：`title` / `url` / `takeaway` / `use`。`use` 为空即视为无效检索，`validate` 报 `N02` 警告。

### 4.3 数据层

`world.json`，10 个顶层段，详见 `references/world-schema.md`。

**设计取舍**
- 用 JSON 而非 YAML：便于脚本与浏览器双向消费
- 允许段为 `null`：支持"先写宇宙、后写生物"的渐进式创作
- 冗余字段（`radius_earth` 与 `radius_km`）：便于人读，且 `validate` 用冗余做交叉校验

### 4.4 计算层 `world_schema.py`

纯函数模块，无 IO、无全局状态。对外只暴露：

```python
load(path) -> dict
validate(world) -> Report          # Report: score, checks[], fatal, warn
compute_derived(world) -> dict     # 密度/重力/平衡温度/开普勒周期
format_report(report, fmt) -> str
axiom_library() -> list[dict]      # 解析 references/公理库.md 的结构化副本
```

**为什么用纯函数**：便于单测、便于被其他 skill 复用、便于未来做 Web 版。

### 4.5 CLI 层 `pangu.py`

六个子命令，见 §6。

**失败语义**：任何子命令出错，退出码非零，错误信息走 stderr，且必须说明**怎么修**（不只说"错了"）。

### 4.6 呈现层

单 HTML，Three.js ESM，自研控制器，程序化纹理。详见 `docs/3D预览层规范.md`。

**核心视觉承诺**：双恒星世界的明暗线上会出现两色过渡带。这是"双影"设定的视觉证据，也是本层存在的理由。

## 5. 关键算法

### 5.1 四数自洽

```
ρ = M × 5.514 / R³                     # g/cm³，R 以地球半径为单位
g = (M / R²) × (G_world / G_earth)     # 以地球 g 为单位
v_esc = 11.19 × sqrt(M / R)            # km/s
```

校验：若 `density_gcc` 与 `gravity_g` 均已给出，与计算值偏差 > 3% 判 `fatal`（P01）。

### 5.2 开普勒第三定律

```
P² = a³ / (M₁ + M₂)     # P: 年, a: AU, M: 太阳质量
```

用于校验 `stars[].orbit` 与 `bodies[].orbit` 的 `a_au` / `period_days` 一致性，容差 ±15%（S04、O01）。

### 5.3 双星稳定判据

```
a_planet ≥ k × a_binary      k = 2.5（保守）/ 2.0（激进下限）
```

- `k < 2.0` → `fatal`（P03）
- `2.0 ≤ k < 2.5` → `warn`

依据：Holman & Wiegert (1999) 的临界半径经验式，取保守值。

### 5.4 洛希极限

```
d_roche ≈ 2.44 × R_p × (ρ_p / ρ_s)^(1/3)
```

卫星轨道 `a < d_roche` → `fatal`（P04）。

### 5.5 平衡温度

```
T_eq = 278.6 × ( (1-A) × L_total / a² )^(1/4)      # K
```

`L_total` 为所有相关恒星的光度之和（环双星时取和）。落在 150–400 K 之外 → `warn`（E01）。
此式忽略温室效应，实际表面温度可高 30–50 K，`note` 中应说明。

### 5.6 宜居带近似

```
HZ_inner ≈ 0.95 × sqrt(L_total)
HZ_outer ≈ 1.37 × sqrt(L_total)
```

仅用于提示，不参与打分。

### 5.7 评分

```
score = clamp(100 − 25×fatal − 4×warn − 2×missing, 0, 100)
```

`missing` 统计为 `null` 的可选段（`biology`、`civilization`、`mathematics`、`chemistry`）。

## 6. CLI 接口规范

### 6.1 子命令总表

| 子命令 | 作用 | 必填参数 | 关键选项 |
|---|---|---|---|
| `init` | 生成骨架 world.json | `--name` | `--seed` `--out` `--autonomy` |
| `validate` | 校验 + 打分 | `world` | `--strict` `--json` `--fix-hint` |
| `preview` | 生成 3D 页 | `world` | `-o/--out` `--title` |
| `export` | 生成世界档案 | `world` | `--md` `--json-out` |
| `axioms` | 查公理库 | — | `--domain` `--roll` `--json` |
| `doctor` | 环境自检 | — | — |

### 6.2 详细签名

```bash
pangu.py init --name <str> [--seed <str>] [--out <path>] [--autonomy auto|co-create|audit]
             [--star-count <int>] [--has-stars | --no-stars]

pangu.py validate <world.json> [--strict] [--json] [--fix-hint]
             # --strict: 有 fatal 时退出码 1
             # --json:   机器可读报告
             # --fix-hint: 每条 fatal/warn 附修补建议

pangu.py preview <world.json> [-o <out.html>] [--title <str>]
             # 缺省输出: 同目录 <meta.id>_preview.html

pangu.py export <world.json> [--md <out.md>] [--json-out <out.json>]
             # 缺省输出: 同目录 世界档案.md

pangu.py axioms [--domain physics|cosmos|math|chemistry|biology|civilization]
             [--roll N] [--json]

pangu.py doctor
```

### 6.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 校验有 fatal（仅 `--strict`）或渲染失败 |
| 2 | 参数错误 / 文件不存在 / JSON 解析失败 |
| 3 | 内部错误（模板缺失、编码异常） |

### 6.4 输出约定

- 人类可读输出走 stdout，UTF-8
- 错误走 stderr，格式 `[ERROR] <阶段>: <说明> → <怎么修>`
- Windows 下强制 `sys.stdout.reconfigure(encoding="utf-8")`，避免中文乱码

## 7. 数据流时序

### 7.1 全自主模式（一轮出全套）

```
User: "造一个三倍地球大的双日照地"
  │
  ├─ L1: 判定 auto 模式 → 斧1 采集（自补 aesthetic/forbidden）
  ├─ L2: 4 次检索（锚定/证伪/取反/质感）→ seed.references[4]
  ├─ L1: 斧2 写 cosmology（恒星/天体/历法）
  ├─ L1: 斧3 写 physics（G'=0.6G 等）
  ├─ L1: 斧4–6 写 chemistry/biology/civilization
  ├─ L1: 斧7 写 history/consistency/narrative
  │
  ├─ L4: validate → 报告（0 fatal, 3 warn, score 88）
  ├─ L1: 按 fix-hint 修 2 处 → validate 再跑 → score 94
  ├─ L5: preview → preview.html
  ├─ L5: export  → 世界档案.md
  └─ L1: 汇总交付 + 给优化建议
```

### 7.2 共创模式

```
斧1 问3题 → 用户答 → 斧1 定
斧2 给3方案(A/B/C 含代价对比) → 用户选 → 斧2 定
… 每斧一次往返 …
斧7 审查 → 有 fatal 则回斧3 → 修完再出
```

## 8. 自洽性引擎

### 8.1 双通道

| 通道 | 执行者 | 负责 |
|---|---|---|
| 机检 | `world_schema.py` | 数值、单位、物理公式、字段完整性 |
| 人检 | agent + `自洽性审查协议.md` | 语义、因果、叙事、代价合理性 |

**机检不能代替人检**：机器算不出"这个代价是否足够"，只能算"这个数是否矛盾"。

### 8.2 检查项清单

17 项，见 `references/world-schema.md` §7。分级：fatal 7 项，warn 10 项。

### 8.3 修补三策

`加代价 > 改设定 > 降野心`。理由见审查协议 §修补三策。

## 10. 跨 harness 可移植性

### 10.1 设计目标

引擎核心本身与平台无关，但"能被加载"这件事依赖宿主约定。1.0 的目标是把**能力**与**加载方式**彻底解耦，使同一份技能在任意 agent / harness 上可用，且**不存在行为分叉**。

三条硬性约束：

| 约束 | 含义 | 违反后果 |
|---|---|---|
| **零厂商依赖** | 不调用任何平台专有工具（如特定 IDE 的 UI 工具、专有记忆接口、平台独占的生成工具） | 换宿主即失效 |
| **零第三方包** | CLI、安装器、MCP 服务器全部只用 Python 标准库 | 用户在受限环境装不上 |
| **单一事实源** | 所有入口最终指向同一份 `SKILL.md` + `references/` + `scripts/` | 多份副本漂移，行为不一致 |

### 10.2 三层解耦架构

```
┌──────────────────────────────────────────────────────────┐
│  L3 入口层（可替换，允许多份）                             │
│  SKILL.md · AGENTS.md · .cursor/*.mdc · GEMINI.md        │
│  · CLAUDE.md · BOOTSTRAP.md · MCP server                 │
│  职责：声明"何时启用 + 去哪读正文"。不含任何业务逻辑。      │
├──────────────────────────────────────────────────────────┤
│  L2 方法论层（唯一，渐进披露）                             │
│  SKILL.md（正文）+ references/（五份按需加载）             │
│  职责：三律、七斧、检索配方、审查协议、字段规范。            │
├──────────────────────────────────────────────────────────┤
│  L1 引擎层（唯一，纯计算）                                 │
│  scripts/pangu.py · world_schema.py · preview_template    │
│  职责：校验、派生量计算、评分、渲染。无网络、无平台假设。    │
└──────────────────────────────────────────────────────────┘
```

**关键决策：入口层只写指针，不复制正文。** 指针文件约 20–40 行，包含技能根绝对路径、四条纪律、启用条件。这样新增一个宿主只需加一个几十行的文件，而不是维护第六份方法论副本。`install.py` 安装时把 `{{PANGU_ROOT}}` 替换为真实路径。

### 10.3 三种加载路径

**路径 A：原生技能目录（最完整）**

宿主按 `SKILL.md` 的 `description` 判断何时加载。要求：

- frontmatter 的 `name` 用 ASCII 短名（`pangu`），避免部分校验器拒绝非 ASCII
- 目录名与 `name` 一致，避免 Claude Code 等以目录名派生技能名的宿主产生不匹配
- 正文自包含，`references/` 靠正文点名加载（渐进披露），避免一次性塞满上下文

**路径 B：指令指针文件**

面向只读项目级约定文件的宿主。指针必须包含三样东西，缺一即失效：

1. **绝对路径**（相对路径在不同 cwd 下会解析失败）
2. **"先完整读 SKILL.md"的硬指令**（否则模型可能只读指针就开始瞎编）
3. **四条纪律的摘要**（即使正文没读到，行为底线仍成立）

`install.py` 用 `<!-- pangu:begin -->` / `<!-- pangu:end -->` 标记块做幂等追加：重复安装替换块内内容，不重复堆叠，也不破坏用户已有的 `AGENTS.md` 其他章节。

**路径 C：MCP 工具服务器**

面向"不支持自定义技能、但支持 MCP"的客户端。实现要点：

| 项 | 决策 | 理由 |
|---|---|---|
| 传输 | stdio，换行分隔 JSON-RPC 2.0 | MCP 标准最低公共子集，兼容性最好 |
| 依赖 | 手写协议，零依赖 | 不强制用户 `pip install mcp` |
| 业务逻辑 | **全部转调 CLI**（`subprocess`） | 不复制逻辑，CLI 与 MCP 永不分叉 |
| 输出 | 只走 stdout；日志/异常走 stderr | stdout 被协议占用，混入日志即协议损坏 |
| 内容上限 | 单次返回 60 000 字符截断 | 防止大文档撑爆客户端上下文 |
| 协议版本 | 回显客户端版本（若在白名单），否则回落 `2024-11-05` | 向前兼容新客户端 |

暴露 7 个 tool：`pangu_guide`（读方法论，支持分段）/ `pangu_doctor` / `pangu_init` / `pangu_validate` / `pangu_preview` / `pangu_export` / `pangu_axioms`。

`pangu_guide` 的意义：MCP 客户端通常不能直接读本地文件，没有它模型就只能凭 `description` 猜方法论。有了它，**即使只走 MCP 一条路，也能拿到完整正文**——这是三条路径行为一致的关键补丁。

**路径 D：纯对话（降级）**

无文件系统、无工具调用的宿主，使用 `adapters/generic/BOOTSTRAP.md`：把三律、七斧、检索配方、审查门槛、交付格式压缩成一份自包含提示词。此路径**不调用任何脚本**，因此没有机检能力，自洽性全靠模型自审——属于有意接受的降级，文档中明确标注。

### 10.4 兼容矩阵与降级阶梯

| 能力 | 完整 | 部分 | 无 |
|---|---|---|---|
| 读本地文件 | 路径 A/B | — | 路径 D |
| 执行 Python | A/B/MCP | — | D（无脚本机检） |
| 联网检索 | 宿主提供 | 无检索（凭知识锚定） | 同左 |
| 3D 预览 | 有浏览器即可 | — | 只出 `world.json` |

降级原则：**能力缺失只降低"校准强度"，不改变"流程正确性"**。七斧顺序、三律、单一数据源在任何路径下都强制生效。

### 10.5 验收标准

| # | 用例 | 期望 |
|---|---|---|
| P1 | `install.py --list` | 列出 7 个 target |
| P2 | `install.py --target all --dest X --dry-run` | 报告全部动作，磁盘无变化 |
| P3 | `--target all` 连跑两次 | 第二次全部为 `replace`，标记块计数仍为 1 |
| P4 | `--skill-dir` 指向技能源内部 | 拒绝执行并给出替代路径（防递归复制自身） |
| P5 | 指针文件占位符 | 安装后 `{{PANGU_ROOT}}` 出现次数为 0 |
| P6 | MCP `initialize` | 返回 `protocolVersion` 与 `serverInfo` |
| P7 | MCP `tools/list` | 返回 7 个 tool，schema 均含 `type: object` |
| P8 | MCP `tools/call` → `pangu_validate` | 返回审查报告，`isError=false` |
| P9 | MCP 未知方法 | `-32601 Method not found` |
| P10 | MCP 未知 tool | `isError=true`，附可读原因 |

## 11. 已知限制

| 限制 | 影响 | 缓解 |
|---|---|---|
| 3D 不表真实比例 | 用户可能误读大小 | HUD 常驻声明 |
| 平衡温度式忽略温室 | 温度可能偏低 30–50 K | `note` 中提示 |
| 只支持 4 个光源 | 四星以上系统光照不全 | 合并最远的星为一束 |
| 不接受 N 体混沌轨道 | 三体真实运动无法模拟 | 用层级近似（hierarchical） |
| 生态模型是定性的 | `trophic_levels.share` 靠人填 | 提供 10% 定律作参照 |
| 无表面第一人称 | 无法"站在地面上看" | v1.1 规划 |
| 纯对话路径无机检 | 路径 D 下自洽性靠模型自审 | 文档明确标注降级；建议改走 A/B/C |
