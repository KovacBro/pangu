## 3. 为什么是观测层

盘古已经有三层：

| 层 | 命令 | 已经能回答 | 机检方式 |
|---|---|---|---|
| 地 | `map` / `ca` / `preview` | 世界长什么样、生态怎么跑 | `map --check` / `ca --check` |
| 改 | `patch` / `sweep` / `diff` / `whatif` | 改一个数会怎样 | 版本 + 重算 + 评分 |
| 推 | `entail` | 已立之律必然导致什么 | 规则触发 + 回写 |
| **看** | **（没有）** | **居民抬头到底看见什么** | **只有 `sky_phenomena` 的自由文本** |

观测层的三个好处：

1. **最便宜**：`cosmology.surface.observer`（纬度/经度/海拔）、`bodies[].axial_tilt_deg` / `rotation_hours` / `atmosphere`、`stars[]` 的轨道与光度、`calendar` 的日长年长——全都已经在 `world.json` 里，缺的只是「算 + 画」。
2. **最上镜**：一张星图比十条命令更适合当封面与第一屏。
3. **能接住「改」**：改倾角、改恒星、改大气，今夜星空立刻变——这是 1.1.2「调参」的延续，也是评论里「想看改造世界」的落点。

**不破 1.1.3 的口径**：只加命令与可选字段；不改 37 项校验的语义；`review` 仍是八项（星空体检挂在 `sky --check`，不塞进交付体检）。

## 4. 大条 A · `sky`：星空与天球

### 4.1 命令面

```bash
pangu sky <world.json>
  [--at "22:10" | --at "暗月3日 22:10" | --at "day=12,hour=22"]
  [--lat 12 --lon 0 --elev 300]      # 缺省读 cosmology.surface.observer
  [--month 3]                        # 一年里的某个月 / 暗月
  [--allnight]                       # 每 2 小时一帧（6 帧）
  [--json | --md [file] | --check | --write]
```

默认输出五段（人读）：

```text
【今夜】赫利孔 · 暗月 3 日 22:10 ｜ 观测点 12.0°N 0.0°E 300m
  极限星等 4.1 ｜ 地平线上约 312 颗 ｜ 银河 不可见 ｜ 月相 上弦（厄瑞玻斯）

【全天】<96×30 ASCII 星图>

【关键天体】
  长明      alt 12°  az 270°
  短烛      alt  9°  az 262°
  远灯      alt 31°  az 180°
  厄瑞玻斯  alt 44°  az 118°  相位 上弦  角直径 1.9°

【一年】昼长 15.0–16.4 h ｜ 极昼 无 ｜ 极夜 无 ｜ 最长夜 暗月 7

【判断】三颗恒星把天空压到约 19.8 mag/arcsec²，银河不可见；肉眼能看见的最暗星约 4.1 等。
```

`--json` 给 agent 与测试；`--md` 出 Markdown（嵌星图 PNG + 表）；`--check` 只跑体检；`--write` 把派生摘要写进 `cosmology.sky`（不写临时时刻）。

### 4.2 算什么（口径写死，误差写明）

| 量 | 算法 | 口径 / 误差 |
|---|---|---|
| 恒星 alt/az | 行星→恒星方向矢量 + 自转时角；圆轨道近似 | 忽略视差与光行时；恒星轨道用 `a_au` / `period_days` / `phase_deg` / `inclination_deg` |
| 行星/卫星 alt/az | 同上，沿 `orbit.parent` 链累加 | 圆轨道；卫星相位按 `phase_deg`（1.1.4 新增可选字段） |
| 昼长 | `cos H0 = -tan φ · tan δ`，`δ = ε · sin(2π(d-d0)/year)` | 忽略大气折射；极昼/极夜按 `|cos H0| > 1` 判 |
| 天空亮度 | 基线 21.9 + 暮光（太阳高度角）+ 月光（相位/高度）+ 尘埃消光 | **经验模型**，误差 ±0.5 mag/arcsec² |
| 极限星等 | 7 mm 瞳孔的经验表，按天空亮度插值 | 暗空 6.5 等；每亮 1 mag/arcsec² 降 0.5–0.7 等 |
| 银河可见性 | 天空亮度阈值 + 银道纬度密度 | 二值（可见/不可见），不给精细亮度图 |
| 月相 / 角直径 | 卫星轨道相位 + 真实半径 | 圆轨道近似 |

**所有输出必须带「简化模型」标注**，不能把 4.1 等说成「精确 4.1 等」。

### 4.3 星图怎么画

- **ASCII**：96×30，地平坐标；底边 0° 地平线，顶 90° 天顶；N/E/S/W 四向；30°/60° 高度圈用 `·` 虚线。
- 符号按视星等：`#`（<0）、`*`（0–2）、`+`（2–4）、`.`（4–极限）；太阳 `@`、行星 `O`、卫星 `C`。
- **PNG**：1200×900，黑底 + 地平线弧 + 方位刻度 + 图例；复用 `scripts/png_writer.py`，不引入 Pillow。
- `PANGU_ASCII=1` 时星图符号也走 ASCII（`#*+.` 已是 ASCII，主要是边框与标注）。
- **不画星座连线**，除非作者在 `starfield.constellations` 里手写。

### 4.4 星表从哪来

**程序生成，不是真实星表。** 这一点写进 README、SKILL、档案与视频，避免被当成 Gaia/HYG 的转述。

```json
"cosmology": {
  "starfield": {
    "seed": 7,
    "count": 2400,
    "magnitude_dist": "power-law",
    "color_mix": {"K": 0.2, "G": 0.5, "F": 0.2, "M": 0.1},
    "galaxy": {"present": true, "inclination_deg": 32, "width_deg": 18, "brightness": 0.6},
    "constellations": []
  }
}
```

- **缺省也能跑**：没有 `starfield` 时按 world 的 `seed`（缺省 0）生成默认 2000 颗，输出标「默认星表（未登记）」；`--check` 给 soft 提示，不报错。
- **可复算**：星表由 `(seed, count, color_mix, galaxy)` 确定性生成；`--write` 存 `starfield.hash`（前 8 位），`sky --check` 重算比对。
- **不引真实星表**：体积、许可、以及「这是本世界的星表，不是地球的」这句设定都要保住。

### 4.5 与 `entail` 的关系：+6 条规则

现有 30 条里，夜空只覆盖了「双影」「不落的灯」「恒黑之天」这类现象，没有一条回答「星星看不看得见」。1.1.4 补 6 条阈值型规则：

| ID | 触发条件 | 推论（居民看见什么） | 强度 |
|---|---|---|---|
| E31 | 恒星 ≥2 且总光度 ≥1.0 L☉ | 夜空不黑，极限星等 ≤4.5，银河不可见 | 必然 |
| E32 | `has_stars == false` | 没有「星」，只有地热/伴星的光；方位靠热源与地形 | 必然 |
| E33 | 有卫星且 `a_km / R_planet < 20` | 月盘大，月相可辨，满月夜能看清影子 | 很可能 |
| E34 | 自转 < 12 h | 星星跑得快，肉眼可见「星移」，长曝光会拉成弧 | 必然 |
| E35 | 倾角 > 45° | 高纬有极昼极夜；夏季整夜有星，冬季整日无星（视纬度） | 必然 |
| E36 | 气压 > 200 kPa | 星光偏红，地平线附近被压扁；星图边缘畸变 | 很可能 |

- 全部可机器判定，出处字段写清；`entail --list` 一并列出。
- `sky --check` 额外做一条「`sky_phenomena` 里说能看见 X，但 `sky` 算出看不见 X」的矛盾检查（只报 warn，不改文本）。

**首个实跑大概率会抓到的真问题**：赫利孔的「远灯」写的是 `0.008 L☉`、约 12 AU，按 1.1.4 的模型实算约 **-16 等**——它不像「一颗不闪的橙红小点」，更像第二颗暗太阳。`sky --check` 应该把这条报出来（天象文本与实算不符）。**先报，不擅自改世界**：改文本还是改光度，是作者的设定决策，不是引擎的。

## 5. 大条 B · 一年昼长与季节

## 6. 大条 C · `whatif --sky`：改一个数，今夜会怎样

`whatif` 已有四层输出（代价 / 审查 / 现象 / 下游）。1.1.4 加第五层「抬头」：

```

  昼长        15.0–16.4 h  →  0–31.4 h（有极昼 / 极夜）
  极昼        无            →  有（每年一段）

```

pangu whatif examples/helikon/world.json --set "cosmology.bodies[0].atmosphere.surface_pressure_kpa=300" --sky

  天空亮度    19.8  →  19.0 mag/arcsec²

## 15. 对着真实世界：还差什么（落地之后补）

> 这一节不是 1.1.4 的范围，是 1.1.4 做完之后回头看：**把这套东西对着真实世界摆一遍，哪里会掉下来。** 结论先给：盘古现在是一个「像」的引擎，不是一个「准」的引擎——每个模块都能给出量级正确的数，但没有一处能对地球做量化复现。差的第一位不是物理公式，是**基准**。

### 15.1 判据：什么叫「像」，什么叫「准」

| | 像（现在） | 准（真实世界） |
|---|---|---|
| 温度 | `t_mean + 55·cosφ − 18`（纬度余弦 + 高度 + 海陆） | `σT⁴ = S(1−α)/4 + G`，逐层辐射传输 |
| 温室 | 作者手填 `greenhouse_delta_k` | 由 CO₂/CH₄/H₂O 分压与谱线算出（地球 33 K） |
| 降水 | 纬向指数衰减 + 地形抬升 | 环流 + 水汽输送 + 云微物理 |
| 星表 | 程序生成、可复算 | 真实天体测量（Gaia） |
| 演化 | 元胞自动机（扩散 + 适应度） | 系统发育 + 种群动力学 |

「像」不是贬义：一个造世工具的第一职责是**自洽**，不是**复现地球**。但两者之间有一条线，叫**可证伪**——把地球的参数丢进去，如果算出来的纬向温度曲线、撒哈拉降水、陆地 NPP 与实测差在 10% 内，它是模型；差 3 倍，它是美术。**盘古目前没有任何一条这样的对表。**

### 15.2 硬差距清单

按「能不能被证伪」排序，不按工作量。

**A. 可证伪性（最要命）**

| # | 现在是什么 | 真实世界是什么 | 差多少 | 影响 |
|---|---|---|---|---|
| A1 | 无地球基准回归 | 给定地球参数应复现 6 条公开曲线 | 从未对表 | 全部 |
| A2 | 温度是纬度余弦插值（`mapgen._temperature`） | 辐射平衡 + 大气廓线 | 纬向**形状**对，绝对值与季节相位差 5–10 K | `map` |
| A3 | `greenhouse_delta_k` 手填 | CO₂ 翻倍 → +3.0 K（AR6 最佳估计，区间 2.5–4.0） | 无法响应成分变化 | `map`、`entail` |
| A4 | `albedo` 手填，无冰-反照率反馈 | 雪线正反馈，极地放大 2–4 倍 | 极区升温低估 | `map` |
| A5 | 生物尺寸由作者拍（灰民 1.2 m） | 克莱伯 3/4 标度、雷诺数、弗劳德数 | 无判据 | `biology` |

**B. 时间（第二要命）**

| # | 现在是什么 | 真实世界是什么 | 差多少 | 影响 |
|---|---|---|---|---|
| B1 | `world.json` 是快照 | 有历史：45 亿年到现在，以及从现在往后的 10 亿年 | 时间轴长度 0 | 全部 |
| B2 | 恒星光度恒定 | 主序 45 亿年 +约 30%，宜居带外移 | 无法回答「他们还有多久」 | `sky`、`entail` |
| B3 | 潮汐锁定是布尔量 | 自转减速（地球日长每世纪 +1.8 ms）、岁差 26000 年 | 星空与历法几千年后会变，引擎不会 | `sky` |
| B4 | 板块是静态 Voronoi + 噪声 | 2–10 cm/yr，1 亿年位移 2000 km，威尔逊旋回 | 有「形」无「史」 | `map` |

### 15.3 只做一件事的话

**`pangu benchmark earth`。**

把地球参数喂进去，跑出六条曲线，与公开数据对表，输出一张偏差表：

| 曲线 | 数据源 | 判据 |
|---|---|---|
| 纬向年均温（°C vs 纬度） | 观测（NASA GISS 分区平均） | 均方根误差 < 5 K |
| 纬向年降水（mm/yr） | 观测（GPCC 分区平均） | 相关系数 > 0.7 |
| 昼长（h vs 纬度/日期） | 解析解 | < 0.1 h |
| 逃逸速度 / 平衡温度 | 解析解 | < 1% |
| 陆地 NPP（Gt C/yr） | 观测 | ±30% |
| 板块速度（cm/yr） | 观测 | 量级正确 |

这张表一旦存在，盘古的每句话都能加前缀「相对地球偏差 N%」——**那是工具与玩具的分界线**。而且它不需要新物理，只需要把已有的模型对着已有数据摆一次，所以它是 1.1.5 里**唯一一件性价比压倒性的事**。

### 15.4 明确不该补的

| 想到过 | 为什么不补 |
|---|---|
| 真实星表 / 精确星历 | 体积、许可，且会杀死「这是本世界的星表」这个设定 |
| CFD 级大气 | 成本指数级，观众看不见，且与「设定工具」定位冲突 |
| 完整系统发育树 | 同上；CA 的抽象度反而是对的，问题在**没有标定**，不在抽象 |
| 无缝 GIS 导出 | 有 `map --write` 的 PNG 与 coarse 场已够 |

盘古的卖点是**可推、可查、可改**，不是**可模拟**。补的每一块都要能落回这三条之一，否则就是给引擎增重。

### 15.5 1.1.5 候选路线

| 优先级 | 条目 | 为什么是它 | 成本 | 观众可见 | 可证伪 |

| **P0** | `benchmark earth` + `review` D9 | 唯一能把「像」变成「准」的动作 | 中 | 低 | ★★★ |

**如果只能做三件**：`benchmark earth`、`map --season`、`NPP → 人口`。前两件一个管「准」，一个管「看」，第三件第一次把世界接到「人」上。

> **2026-11-04 更新：这三件已经并进 1.1.4 了**（不是留给 1.1.5）。做法见 §16。

**1.1.4 → 1.1.5 的关系**：1.1.4 是**看得见**（美术），1.1.5 应该是**经得起对表**（基准）。前者靠一张星图，后者靠一张偏差表——一张星图能被转发，一张偏差表能被引用。

### 15.6 对外表述的边界

- 可以说：「盘古的每个模型都标了误差与适用域，`benchmark earth` 会告诉你它离地球差多少。」
- 不可以说：「盘古能精确模拟一个行星。」
- 可以说：「它没做洋流，所以同纬度的西岸与东岸一样暖——这是已知偏差，写在偏差表里。」
- 不可以说：「这是真实世界的物理引擎。」

**已知偏差要主动写在输出里**，和 1.1.4 给星图标「简化模型 ±0.5 等」是同一个规矩：**先认账，再交付。**

### 16.2 基准第一天抓到的两个真错

这张表不是装饰。第一次跑出来是 **4/6**：

1. **B02 纬向降水 r = 0.40**。原因两条：
   - 蒸发写成 `if temp < 268: continue` —— 极区一刀切归零，于是极地下不了雨（模型给 3 mm/yr，实际 150 mm）。
   - 副热带下沉支（Hadley 下降流）**根本没有建模**，25° 比赤道还湿。
   修法：蒸发改成 `max(0, T−250)/30` 并加背景源；加 `subs = exp(-((|lat|−28)/11)²)`，下沉支**抑制**成雨（`k × (1−0.55·subs)`）而不是增加。
2. **B01 纬向温度 RMSE 30.7 K** —— 但这是**基准自己的 bug**：`_zonal_mean` 拿行索引去索引展平场，取了整条错的带。修完 30.7 → 6.7 K。

修完：**6/6 通过**，纬向降水 **r = 0.817**、纬向温度 **RMSE 6.72 K**、昼长 **RMSE 0.023 h**、逃逸速度 0.04%、平衡温度 0.27%、陆地 NPP 61.3 Gt C/yr（+9.5%，阈值 ±35%）。
